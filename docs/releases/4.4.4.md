中文标题：**定时加密备份与保留治理**

4.4.3 把单次备份与恢复焊结实之后，4.4.4 进入自动化阶段：独立 Backup Policy、
密封 Frontend Replica Mirror、无人值守 Age 往返验证、耐久调度器、原子目标发布、
Hash Chain Catalog 与可预览的 GFS 保留治理。

## 耐久定时备份策略

- Backup Policy 只持久化公开 `age1...` Recipient；定时备份拒绝 Passphrase，Recovery Identity 永不落盘。
- Policy 包含 IANA 时区 Cron、Misfire Policy、Catch-up Window、Jitter、Scope、Frontend Mirror 模式、目标与保留策略引用、重试边界。
- Policy 字段拒绝私钥、密码、Token 与 Redis 凭据；恢复工作区后旧 Policy 以 disabled/unbound 状态回归，必须手动重新绑定并启用。

## 密封 Frontend Replica Mirror

- 浏览器在 Durable Head 变化时上传 Frontend Envelope，服务端再次验证 Digest 后立即用 Policy Recipient 加密为 Age 文件。
- 镜像元数据只含 Epoch、Digest、Recipient Set 摘要与计数，不含标题、正文、Draft、Writer ID 或 Recovery Identity。
- 旧 Epoch、过期 Generation、Restore Fence 期间的上传被拒绝；相同 Digest 幂等跳过；保留一个 Previous Mirror。

## 无人值守往返验证

- 每次运行生成临时 Age Identity，与用户 Recipient 一同加密，随即用临时 Identity 解密并校验 ZIP、Manifest、Coverage 与 Frontend Mirror。
- 临时 Identity 清零销毁；最终密文仍只能由用户的 Recovery Identity 解锁。
- Catalog 区分 `creationVerified`、`ciphertextScrubbedAt` 与 `userUnlockVerifiedAt`。

## 耐久调度器与租约

- SQLite 调度库记录 Policy、Schedule Slot、Run、Lease 与 Target Health；`UNIQUE(policy_id, schedule_slot)` 保证多进程恰好一次。
- Slot 计算覆盖 IANA 时区、DST 缺失/重复本地时间、停机补跑（最多一次）与确定性 Jitter。
- Worker 失去 Lease 后不得发布、更新 Catalog 或执行 Retention；Restore Fence 活跃时 Run 进入 `deferred: workspace-restore-active`。

## 目标注册与原子发布

- 文件系统目标以 `.deepseek-infra-backup-target.json` Marker 识别，与盘符/挂载路径无关。
- 拒绝位于 Runtime Root、源码仓库、Contributor Root、Restore Staging、系统临时目录或符号链接后方的目标。
- 发布经 `.partial` 暂存、fsync、目标端 SHA-256 复算、Receipt 原子改名与目录 fsync；目标离线不回退内部磁盘。

## Catalog 与保留治理

- 每个成功文件对应一条 Receipt；Catalog 为追加式 Hash Chain，可由 Receipt 重建，恢复信任根仍是 Age、Manifest 与逐文件摘要。
- GFS 保留按 Policy 时区分桶，仅在新备份成功发布后执行；Preview 先行，删除经 `.trash` 与 Grace Period 两阶段。
- Pinned、最新健康副本、Restore 引用、Safety Backup 引用与活跃 Run 文件永不自动删除。
