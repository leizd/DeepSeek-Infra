中文标题：**有效快照去重索引与跨文件块复用**

4.4.10 把真实 Delta 的生成和恢复收紧成有界、可恢复、可原生加速的闭环。4.4.11 修复 Chunk Index 无法继承未变化文件的根问题，并在不改变 Age 隐私边界和远端 Commit 模型的前提下增加跨文件复用。

## Effective Snapshot Chunk State

- 本地 `.backup-index` 使用不可变 `chunk_maps`、`chunk_map_chunks` 和 `snapshot_chunk_refs`；`chunk_map_id` 由 Chunk Protocol、文件大小和文件 SHA-256 确定。
- Child Snapshot 只继承未变化文件的 Map Reference，不复制所有 Chunk Row；因此 Map 可穿过任意数量的未变化 Incremental。
- Lineage、Effective Files、新 Map 和 Effective Ref 在 `BEGIN IMMEDIATE` 事务中一次提交。任何冲突或损坏都会回滚、耐久标记 stale，并强制下一次 Full。
- 旧 `snapshot_chunks` 只迁移一次；协议未知、断裂 Lineage 或不连续 Map 不做猜测。Retention 完成物理删除后再清理 Snapshot Row 与无引用 Map，不在每轮执行 `VACUUM`。

## Immediate Parent 跨文件复用

- Builder 先在相同文件查找，再对 Immediate Parent Effective Snapshot 做全局、批量、精确的 `(SHA-256, length)` 查询。
- 新文件可以引用 Parent 其他文件的 Chunk；同摘要且同长度是必要条件，引用不会越过 Immediate Parent 建立新的历史依赖边。
- Rename/Copy 的完整内容若已存在于 Parent，可用 `storage: parent-file` 实现零 Payload。
- Bloom Filter 只存于本地索引，仅排除确定不存在的 Candidate；任何正匹配仍必须经过 SQLite。Bloom 缺失或损坏最多降低复用率，不能产生错误引用。

## Incremental v4 与 Immutable Parent Restore

- 新加密 Manifest 使用 `incremental-v4` 和 `source: parent-range`，直接携带 Parent Path、Offset、Length 与 Chunk SHA；FastCDC 生成协议仍是 `fastcdc-gear-v3`。
- 已提交的 `incremental-v2/v3` 继续使用版本化 `parentOrdinal` 解码，恢复兼容性不变。
- Materializer 先在只读 Parent Tree 上准备并校验所有 PUT，再应用 Tombstone 和原子替换。文件互换、先删后拷、跨文件 Range 和整文件 Parent Copy 都不会读到本层已修改的数据。

## Rust Batch 与真实回退遥测

- `deepseek-backup scan-batch` 从 stdin 消费 JSONL、向 stdout 输出逐项 JSONL，让一批大文件共享一个 Helper Process。
- Python 侧按实际结果报告 `rustFiles`、`pythonFallbackFiles` 和聚合 `fallbackReasons`；回退率超过 10% 标记 `degraded`，但仍由 Python 权威实现正确完成。
- 去重遥测只包含逻辑/物理字节、复用数量、Bloom 命中和精确查找计数，不包含路径、文件 Hash 或 Chunk Hash。

## S3 Fail Closed

- Multipart Complete 冲突只有在目标对象同时满足预期 SHA-256 Metadata 和预期长度时才能收敛为成功。
- 已存在但摘要缺失、摘要不符或长度不符的非空对象返回 `object-integrity-unproven`。
- Capability Probe 会实际完成 Multipart 并回读 Metadata；不保留摘要的 S3-compatible Provider 不能进入 Scheduled Ready。

## 明确边界

本版本不引入 Convergent Encryption、确定性 Age、云端 Plaintext Chunk Hash Index、独立 Chunk S3 Objects、跨 Target/Policy 去重、对已从 Immediate Parent 删除内容的历史引用、数据库 WAL 增量或 WebDAV GA。

## 验收一句话

> 一个大文件的 Chunk Map 必须能够无损穿过任意数量的“该文件未变化”Incremental；如果当前 Snapshot 中另一个文件已经拥有相同 Chunk，则新文件只能记录对 Immediate Parent Byte Range 的加密 Manifest 引用，而不得重复写 Payload。所有跨文件引用都必须在 Immutable Parent View 上先完整准备和校验，再提交 Delete/Put；Bloom 与本地 Chunk Index 只能影响复用率，任何损坏都不得影响备份或恢复正确性。
