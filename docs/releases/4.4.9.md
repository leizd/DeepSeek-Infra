中文标题：**真实差分存储与可验证增量恢复**

4.4.8 把 Incremental 的控制面接通了，但数据面还有几处硬缺口。4.4.9 把「会生成 Incremental 元数据」推进到「目标上真的只存变化数据，并且真的能从 Full + Delta 恢复」。

## 真实差分包（incremental-v3）

- Age 包里**不再包含完整 `payload/<contributor>/...`**，只保留：
  - `manifest.json` / `checksums.sha256`
  - `delta/operations.json`
  - `payload/files/<id>`（whole-file 与 CDC chunk 的内容寻址 blob）
- `operations.json` 在所有 Payload 引用分配完成后才序列化，落盘的 `payloadRef` 是最终真实路径。
- 同一 Delta 中相同 `sha256` 只生成一个 Blob（whole-file 去重）。

## 稳定的 Content-Defined Deltas

- FastCDC 协议升级为 `fastcdc-gear-v2`：偏移连续（`next.offset == previous.offset + previous.length`）、Golden Corpus 钉死边界、min/avg/max 固定；`fastcdc-gear-v1` 仅作实验格式，不允许成为生产 Parent。
- 生产 Builder 接上 CDC：变化的大文件 → 载入 Parent Chunk Map → Streaming CDC → 对比 Chunk → 只写新 Chunk → Commit 后持久化新 Chunk Map。

## 完整 Lineage 与可验证 Chain Restore

- `baseBackupId` 贯穿整条链（Full Baseline），`parentBackupId` 指向直接父级。
- Force-Full 条件从已提交元数据真实计算（scope / recipient / schema digest、logical bytes、chunk protocol、full interval、chain depth）；delta ratio 需要构建期后的 delta 大小，保留为后续增强。
- Restore 建立持久 Chain Session：`F0→I1→…→Iₙ` 逐层下载、解密、应用并验证 Merkle Root；最后只把一个完整 Workspace Tree 交给现有 Federated Restore。缺失任一必要层即 Fail Closed。

## Retention 与报告

- 祖先保护基于 `recoverableRecords`：Trash Grace 内的可恢复后代仍保护其祖先；只有 Child 最终 Physical Delete 后 Parent 才失去依赖保护。
- 备份报告物理增量节省（delta payload bytes vs logical changed bytes）。

## 明确不做（推迟到 4.4.10）

跨文件 Chunk Reuse、跨 Backup 云端 Chunk CAS、Bloom Filter、Rust Chunker、并行 CDC、Convergent Encryption、独立 Chunk S3 Objects、数据库 WAL 增量、WebDAV。

## 验收一句话

> Incremental I1 的 Age 包里不允许再出现未变化的 Workspace 文件；删除 Full F0 或任一必要 Delta 后恢复必须 Fail Closed。一个 1 GiB 文件只修改 4 MiB 后，新 Incremental 的 Payload 必须接近变化 Chunk 大小。恢复 Iₙ 时必须真正下载、解密并依次应用 F0→I1→…→Iₙ，在每一层通过 Merkle 校验后，最终 Workspace 与源快照逐字节一致。
