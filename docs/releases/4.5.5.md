Release date: **2026-08-17**.

4.5.5 delivers **Verified Write Continuity & Primary Promotion (可验证写入连续性与主目标提升)**. It elevates multi-target backup write failover from a configuration resolution choice to a cryptographically proven, single-encryption continuous pipeline with governed failback and explicit administrative primary promotion.

## Highlights

1. **True Multipart Streaming Remote Repair ($O(\text{buffer}\times\text{workers})$ RAM)**  
   Eliminates all in-memory full-component buffering across remote S3 stores during replica repair. Transfers stream bounded 8 MiB chunks directly through S3 multipart upload APIs (`begin_multipart` / `upload_part` / `complete_multipart_if_absent`). Destination verification and quarantine operations operate fully via streaming digests.

2. **CAS-Guarded Protection Lease Renewal with Immediate Fail-Closed**  
   Remote source holds are renewed using conditional `put_if_match` with strict ETag verification. Any CAS conflict or lease loss raises `RepairLeaseLostError` and aborts repair immediately before any subsequent source data reads.

3. **Formal Control-Plane Authentication Helper (`authenticate_recovery_copy`)**  
   Unifies recovery copy validation across source and destination targets. Verifies raw Receipt SHA-256 hash bindings against Commit markers, validates schema and policy bindings, and checks `objectSetDigest`. Corrupted or mismatched control planes are transitioned to `quarantined`.

4. **Durable Retry Policy, Error Classification & Keyset Reconciler**  
   Classifies replication/repair errors into retryable network backoffs, source-degradation re-selections, and fatal terminations with exponential backoff and jitter. The background reconciler tracks durable `(policyId, afterCommittedAt, afterLogicalId)` keyset cursors that wrap around to visit all historical retained points.

5. **Capability vs Fresh Liveness Decoupling**  
   Decouples static capability evidence (`scheduledBackupCompatible`, `multipartUpload`, `integrityMode`) from dynamic liveness evidence (`status`, `observedAt`, `latencyMs`). Liveness is verified with fresh preflights (<=120s caching), ensuring DR readiness polling executes with **zero remote I/O and zero side effects**.

6. **Immutable Package Plan with Mutable Write Placement Journal**  
   Separates immutable backup package identities (`backupId`, `snapshotKind`, `contributors`, `recipientSetDigest`, `objectSetDigest`, `spoolDigest`) from mutable placement journals. Write failover transitions targets using the identical frozen encrypted package without re-snapshotting, re-packing, or re-encrypting.

7. **Ambiguous Commit Reconciliation**  
   Network timeouts during primary target commit attempts trigger formal commit slot reconciliation. If the primary commit marker exists and is valid, the write is confirmed; if definitively absent, the frozen package safely transitions to a replica target; if indeterminate, the phase transitions to `ambiguous-write`.

8. **Governed Failback with Stability Window & Recovery Point Convergence**  
   Automatic failback to a recovered primary requires continuous healthy liveness across a configurable stability window (default 1800s) and verified convergence of the latest logical recovery point on the primary. Failback executes strictly on the next schedule slot without disrupting in-flight runs.

9. **Explicit Primary Promotion with CAS Preconditions**  
   Administrative endpoint `POST /api/workspace/backup-policies/{policyId}/promote-primary` upgrades a healthy Required Replica to configured Primary under CAS checks (`expectedPolicyRevision`, `expectedFailoverEpoch`). The former primary is preserved as a Required Replica without rewriting historical backups.

10. **Target Placement Failure Domain Metadata**  
    Target definitions support optional placement metadata (`region`, `failureDomain`, `priority`, `costClass`), enabling policies to enforce multi-failure-domain redundancy compliance (`minFailureDomains`).

## Compatibility

- Frozen wire formats: `object-set-v1`, Receipt v4, Commit v4, FastCDC v3, randomized Age encryption.
- Fully offline evaluation gates: RAG, Tool, Security Corpus, Injection Adversarial, and Agent Eval gates pass strictly.
