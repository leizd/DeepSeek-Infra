Release date: **2026-08-16**.

4.5.2 delivers **Recovery Replica Sets & Automatic Target Failover** on the frozen
`object-set-v1` / Receipt v4 / Commit v4 / randomized Age wire formats, and closes
the production lifecycle gaps left from 4.5.1 Recovery Assurance.

## Highlights

1. **Recovery Replica Sets (policy.replication)**  
   Backward-compatible policy block keeps `targetId` as Primary and adds optional
   required / best-effort replicas with `minCommittedCopies`. Secrets never enter
   the policy file.

2. **Encrypt once, publish many**  
   Build → Age encrypt once → primary publish → durable replica jobs. Replica
   targets re-emit target-local Receipt v4 / Commit v4 over the same ciphertext
   digests. Primary commit is never rolled back when a replica fails.

3. **Durable BackupReplicationJob**  
   Restart-safe phases through `committed` / `failed`. Content-addressed converge.
   Required replica spool retention until terminal.

4. **Replica-aware DR Evidence Ledger**  
   Logical recovery points group copies by `backupId` + policy + object-set
   commitment. Readiness reports `committedCopies`, `healthyCopies`,
   `requiredCopies`, `replicationCompliance`.

5. **Recovery Planner (ledger-only)**  
   `POST /api/workspace/disaster-recovery/plan` ranks compatible targets with
   explicit reason codes and zero remote I/O.

6. **Automatic Target Failover**  
   Single active source target. Failover only before live prepare. New hold is
   established before old hold release. Identity / projection / workspace errors
   do not failover. `maxFailovers` prevents A→B→A loops. Verified ciphertext
   cache survives by digest.

7. **4.5.1 P0 production wiring**  
   Global RecoveryLeaseKeeper lifecycle, terminal-only phase exclusion, real
   lease health, scheduled drill durable cron slots, strict policy evidence
   scope, durable audit jobs, production telemetry → ledger, honest calibrated RTO.

## Compatibility

- Unchanged: `object-set-v1`, Receipt v4, Commit v4, fastcdc-gear-v3, randomized Age.
- Whole-Age and incremental-v2/v3/v4 restore paths remain supported.
- Not introduced: object-set-v2, Receipt/Commit v5, convergent/deterministic Age,
  multi-source component restore, failover after prepared/commit.

## Evidence contract

See `docs/EVIDENCE_INDEX.md` and `docs/evidence/*-v4.5.2.json` producers.
Real two-target MinIO E2E requires independent bucket/prefix targets and proves
identical ciphertext SHA256 across replicas.
