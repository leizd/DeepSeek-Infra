中文标题：**投影式恢复与生产级远端恢复闭环**

4.4.12 完成了 Packed Delta 与持久化快照状态。4.4.13 处理恢复体验与生产闭环：用户不必恢复整个 Workspace，可以只恢复指定的 Contributor / Project；同时把 MinIO E2E 里仍然存在的「拼装测试」换成真正的生产 Backup → Age → S3 → Receipt → Restore → Federated Commit 全链路。

## 投影式恢复（Projected Restore）

- 创建 Restore Session 时冻结 `selection`（`contributors` + `projectIds`），并持久化 `selectionDigest`。Retry 时选择摘要不一致直接返回 `409 restore-selection-mismatch`，选择一旦冻结不可改变。
- 投影粒度先按 Contributor 能力定义：`projects → project`，其余 Contributor → `contributor`。第一版不支持任意 glob / 任意路径 / 任意 JSON 子树。
- 只有被选中的 Workspace 范围会被物化并写入；未选中的 Contributor 绝不被改动。

## Dependency Closure：Output 与 Support 严格分离

- 被选中文件可能通过跨文件 `parent-range` 依赖一个未被选中的父文件（例如 `projects/B.bin` 依赖 `cache/A.bin`）。该类依赖自动进入只读 Support 集，在 scratch 中物化并参与校验，但**绝不**进入最终 Workspace。
- 定义两个严格分开的集合：`restoreOutputSet`（最终写入）与 `restoreDependencySet`（仅支持物化）。

## 完整性语义：Metadata Plane Full，Payload Plane Projected

- 元数据平面仍然完整验证：F0 Manifest + 完整 FileRecord State，逐层应用 PUT/DELETE，逐层校验 `rootDigest`，整条 Merkle 链不能因选择性物化而跳过。
- 正文 Byte Materialization 才做选择性：只提取所需的 Full 文件、所需的 Pack、所需的 Standalone Blob。

## 诚实的上报：Whole-Age Object

- 远端 Backup 仍是「整包 ZIP → 整个 Age 加密 → 单个 `.age` Object」的模型。投影可以节省解压文件数、临时磁盘、Pack Range 读取、Delta Materialization 与最终写入，但**不能节省 S3 密文下载量**。
- Preview / API 必须明确报告 `networkSelective: false` 与 `networkSelectivityReason: "whole-age-object"`，不把选择性物化宣传成网络级 Selective Fetch。

## Selective 解压与懒验证

- Remote Restore 只读取 `manifest.json`、`delta/operations.json`、`payload/packs/index.json`，跑完 Projection Planner 后只解压所需条目。
- Pack Index 先做纯解析验证（schema / paths / ranges / overlap / metadata），Pack SHA-256 只在首次真正使用时验证；全量恢复自然会把全部 Pack 验完。

## Federated Restore 与交易摘要

- `prepare_restore` 按冻结的 selection 处理 operation；`serverTransactionDigest` 纳入 `selectionDigest`，避免「同一 staged contributor set + 不同 selection」撞出同一交易摘要。
- `requiresFrontendApply` / `requiresExternalMcp` 由 selection 推导：只恢复 Project A 时不再弹出 Frontend Restore 确认，未选择 external MCP 时绝不启动 distributed prepare。
- Safety Backup 仍然始终 Full；恢复可以 Partial，回滚兜底永远完整。

## Hold 生命周期

- Complete / Abort / Federated 交易前失败 → 释放所有祖先 Hold；`recovery-required` → 保留。TTL 仍是最终兜底。

## 成本模型修正与索引维护

- Adaptive Full 的决策从「纯正文 payload」改为 Pack Finalize 后的真实容器成本（Pack 总大小 + Pack Index + Standalone + Operations + ZIP 开销），再与 Full 归档估算对比。
- Index Maintenance 增加迁移路径：maintenance requested → 新建 DB → 复制 live state → 校验 head/root → fsync → 原子 swap → 成功前保留旧 DB；不在 Scheduler Critical Path 上执行完整 `VACUUM`。

## 生产 Remote Restore E2E

- CI 使用真实 MinIO + 真实 boto3/S3TargetStore + 真实 Age Helper（`rust/crates/backup-crypto`）驱动 Policy → Scheduler → Executor → 真实 Backup → 真实加密 → spool → multipart S3 → Slot Commit → Receipt → Catalog。
- 制造 F0 → 修改 Workspace → I1 `incremental-v5`，模拟新进程 / 清空运行时状态后走 `create_restore_from_target()` → 解析 Receipt 链 → 创建祖先 Hold → `fetch_restore_session()` → 真实密文 SHA → 真实 Age 解密 → Projection → 物化 → `prepare_restore` → commit → complete。
- 验收：Workspace 与 I1 Snapshot 字节级一致。

## 明确边界

本版本**不做网络级 Selective Fetch**：继续不引入独立加密 Pack S3 Objects、云端 Chunk CAS、Convergent/Deterministic Age、云端 Plaintext Chunk Hash、跨 Policy/Target 去重、Immediate Parent 之外的历史引用、数据库 WAL 增量或 WebDAV。打包 Index v2（每 Pack 紧凑 Entry、去重 Blob SHA）延后到 4.4.14。真正把「1 Snapshot = 1 Age Object」改成「Encrypted Manifest + 独立 Encrypted Pack Objects」的协议跃迁，留给 4.4.14 及以后单独设计。

## 验收一句话

> 用户必须能够把一次 Remote Restore 冻结为明确的 Contributor/Project Projection，只修改被选中的 Workspace 范围；任何跨文件 `parent-range` 依赖都自动进入只读 Dependency Closure，但不得成为最终写入。即使只恢复部分内容，F0→I1→…→In 的完整逻辑 Snapshot 仍必须逐层通过 Merkle 验证。由于本版继续采用 Whole-Age Object，API/UI 必须明确报告整个密文链仍需下载，不能把选择性物化宣传成网络级 Selective Fetch。同时 MinIO E2E 必须真正通过生产 Age、Executor、Slot Commit、Receipt/Catalog、Remote Restore 与 Federated Commit/Complete 全链路。
