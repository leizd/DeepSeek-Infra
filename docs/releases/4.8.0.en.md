**Applicable version:** v4.8.0 candidate implementation

**Subtitle:** Mutual Trust, Receiver-Controlled Ingress, Offsite Replica
Attestation & Federated DR

4.8.0 lets two sovereign Fleets establish cryptographically verifiable offsite
custody and recovery without sharing Authority, Age private identities, or
storage credentials.

## Closed loop

- Gate A closes schedule identity rebinding: same ID/same digest is idempotent,
  same ID/different digest returns `SCHEDULE_IDENTITY_CONFLICT`, and running or
  terminal schedules cannot be rewritten.
- Schedule and wave runner leases renew. A real two-OS-process SIGKILL takeover
  uses higher schedule/wave/action epochs and the same underlying effect ID,
  producing one MinIO effect.
- A dedicated Ed25519 Fleet root and short-lived online signer remain separate
  from randomized Age and Control Authority. Pinned-root certificates and
  monotonic sequences govern signer rotation and revocation.
- The Peer Trust Registry implements
  `PENDING -> VERIFIED -> ACTIVE -> SUSPENDED -> REVOKED`, requires operators to
  pin the root fingerprint and provider/region/jurisdiction/siteClass, and rejects
  TOFU, identity collisions, and self-declared failure domains.
- Signed readiness binds the full canonical snapshot. Challenge/response binds
  the nonce, both Fleet IDs, signer, and time window and rejects replay,
  future/expired documents, and revoked identities.
- Receiver issues a short-lived scoped ingress grant bound to transfer, policy,
  backup, object set, prefix, byte ceiling, nonce, and validity. Sender never
  receives Receiver's long-lived credentials.
- The immutable transfer journal binds source, destination, backup, and object set
  to one `transferId`. Partitions and unknown outcomes require GET/reconcile before
  retry; blind replay is forbidden.
- Federation sends the existing randomized-Age ciphertext and `object-set-v1`.
  Receiver creates Receipt v4 and Commit v4 through the production storage path
  and returns a signed replica attestation. Sender records
  `FEDERATED_COMMITTED` only after validating every binding.
- `minFederatedCopies`, `minDistinctFleets`, `maxFederatedCopyAge`,
  `allowedPeerFleets`, and `allowedJurisdictions` remain independent from local
  durability. Remote copies cannot lower local copies/domains or authorize
  promotion, mutation, pruning, or deletion.
- `COLD_CUSTODY` proves ciphertext custody only. `RECOVERY_CAPABLE` uses an Age
  identity provisioned outside Federation to run production restore into an
  isolated workspace and returns a semantically validated signed DR attestation
  that requires successful cleanup.

## Real Evidence

The dedicated scenario starts two independent Fleet roots, Authorities, journals,
and HTTP processes plus four logical MinIO targets. The shared CI harness retains
one additional legacy target, so the producer starts five independent MinIO
endpoints while Federation uses only four. Fleet A and B storage principals are
isolated and actual cross-authentication attempts are denied.

The scenario performs a real randomized-Age Backup, pinned trust,
challenge/readiness, Receiver ingress, ciphertext upload, Receipt v4/Commit v4,
signed replica verification, Receiver mid-transfer SIGKILL/new-PID resume, grant
replay rejection, attestation tamper rejection, peer revocation, and a production
federated DR restore.

The dedicated exact artifacts are:

- `federation-trust-proof-v4.8.0.json` (15 typed checks);
- `federated-replica-proof-v4.8.0.json` (37 typed checks, including runtime/process proof);
- `federated-dr-proof-v4.8.0.json` (10 typed checks).

The local real-MinIO scenario and semantic validators pass, which qualifies the
candidate implementation only. Formal release PASS still requires the final PR
head/merge SHA's CI producer to upload the same exact bytes, match report SHA-256
and byte size, and pass global Evidence Assembly.

## Wire freeze

`object-set-v1`, Receipt v4, Commit v4, FastCDC v3, Projection semantics,
randomized Age, `control-authority-v1`, AuthorityCheckpoint v1,
`dr-readiness-proof-v1`, the `evidence-proof-v2` envelope, and
`predictive-planning-proof-v1` remain unchanged.

The new `federation-readiness-attestation-v1`,
`federation-ingress-grant-v1`, `federated-replica-attestation-v1`, and
`federated-dr-drill-attestation-v1` schemas are Federation control/evidence
documents, not storage wire upgrades.

## Explicit non-goals

Automatic cross-Fleet primary promotion, shared or multi-primary Authority,
Raft/global consensus, cross-Fleet policy mutation or delete, automatic local
replica pruning, remote copies replacing local durability, transmission of Age
private identities, TOFU, LLM-based trust/routing, and Receipt v5, Commit v5,
`object-set-v2`, or `control-authority-v2`.

See the [Signed Federation and Cross-Fleet DR runbook](../runbooks/SIGNED_FEDERATION_DR.md)
and [ADR-0048](../adr/ADR-0048-signed-federation-cross-fleet-dr.md).
