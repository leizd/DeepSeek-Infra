**适用版本：** v4.8.0 候选实现

**副标题：** Mutual Trust, Receiver-Controlled Ingress, Offsite Replica
Attestation & Federated DR

4.8.0 让两个各自主权完整的 Fleet 建立密码学可验证的异地 custody 与 recovery，
而不共享 Authority、Age private identity 或 storage credentials。

## 本版闭环

- Gate A 关闭 schedule identity 重绑定：same ID/same digest 幂等，same ID/different
  digest 返回 `SCHEDULE_IDENTITY_CONFLICT`；运行中和 terminal schedule 不可重写。
- Schedule/wave runner lease 可续租。真实双 OS-process SIGKILL 证明接管使用更高
  schedule/wave/action epoch，并复用同一个 underlying effect ID，不重复 MinIO effect。
- Dedicated Ed25519 Fleet root 与短期 online signer 独立于 randomized Age 和 Control
  Authority。Signer rotation/revocation 由 pinned root certificate 和单调 sequence
  约束。
- Peer Trust Registry 实现 `PENDING -> VERIFIED -> ACTIVE -> SUSPENDED -> REVOKED`，
  强制 operator pin root fingerprint 与 provider/region/jurisdiction/siteClass，拒绝
  TOFU、identity collision 和自报 failure domain。
- Signed readiness 绑定 full canonical snapshot；challenge/response 绑定 nonce、双向
  Fleet IDs、signer 和时间窗，并拒绝 replay、future/expired 与 revoked identity。
- Receiver 签发短期 scoped ingress grant；grant 精确绑定 transfer、policy、backup、
  object-set、prefix、byte ceiling、nonce 和有效期。Sender 不接触 Receiver 长期凭据。
- Immutable transfer journal 将 source/destination/backup/object-set 绑定到单一
  `transferId`。分区或未知结果后先 GET/reconcile，禁止 blind retry。
- Federation 传输既有 randomized-Age ciphertext/`object-set-v1`。Receiver 通过
  production storage path 创建 Receipt v4 与 Commit v4，并返回 signed replica
  attestation；Sender 验证全部 binding 后才记录 `FEDERATED_COMMITTED`。
- `minFederatedCopies`、`minDistinctFleets`、`maxFederatedCopyAge`、
  `allowedPeerFleets` 和 `allowedJurisdictions` 独立于 local durability。Remote copy
  不能降低 local copies/domains，也不能 promotion、mutation、prune 或 delete。
- `COLD_CUSTODY` 只能证明密文 custody；`RECOVERY_CAPABLE` 使用 federation 外预配置
  的 Age identity 运行 production restore 到 isolated workspace，并返回语义可验证
  且要求 cleanup 成功的 signed DR attestation。

## 真实 Evidence

Dedicated scenario 启动两个独立 Fleet roots/Authorities/journals/HTTP processes 与
四个逻辑 MinIO targets。共享 CI harness 另保留一个 legacy target，因此 producer
实际启动五个独立 MinIO endpoint；Federation 场景只使用四个，且 A/B Fleet storage
principals 相互隔离并通过真实 cross-auth denial 证明。

场景执行真实 randomized-Age Backup、pinned trust、challenge/readiness、Receiver
ingress、ciphertext upload、Receipt v4/Commit v4、signed replica verification、
Receiver mid-transfer SIGKILL/new-PID resume、grant replay rejection、attestation
tamper rejection、peer revocation 和 production federated DR restore。

三个 dedicated exact artifacts 为：

- `federation-trust-proof-v4.8.0.json`（15 typed checks）；
- `federated-replica-proof-v4.8.0.json`（37 typed checks，包含 runtime/process proof）；
- `federated-dr-proof-v4.8.0.json`（10 typed checks）。

本地真实 MinIO 场景与 semantic validators 已通过，只能证明候选实现。正式 release
PASS 仍要求最终 PR head/merge SHA 的 CI producer 上传同一 exact bytes、报告中的
SHA-256/byte size 匹配，并由全局 Evidence Assembly 重新验证。

## Wire freeze

`object-set-v1`、Receipt v4、Commit v4、FastCDC v3、Projection semantics、
randomized Age、`control-authority-v1`、AuthorityCheckpoint v1、
`dr-readiness-proof-v1`、`evidence-proof-v2` envelope 与
`predictive-planning-proof-v1` 完全不变。

新增 `federation-readiness-attestation-v1`、`federation-ingress-grant-v1`、
`federated-replica-attestation-v1` 与 `federated-dr-drill-attestation-v1` 是
Federation control/evidence documents，不是 storage wire 升级。

## 明确不做

Automatic cross-Fleet primary promotion、shared/multi-primary Authority、Raft/global
consensus、cross-Fleet policy mutation/delete、automatic local replica pruning、remote
copy 替代 local durability、传输 Age private identity、TOFU、LLM-based trust/routing，
以及 Receipt v5、Commit v5、`object-set-v2`、`control-authority-v2`。

运维流程见 [Signed Federation 与跨 Fleet DR 运维手册](../runbooks/SIGNED_FEDERATION_DR.md)，
架构决策见 [ADR-0048](../adr/ADR-0048-signed-federation-cross-fleet-dr.md)。
