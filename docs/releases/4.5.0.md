Status: **in development; not release-ready**.

4.5.0 freezes object-set-v1, Receipt v4, Commit v4, randomized Age encryption,
Projection semantics, and permanent Whole-Age compatibility. Implementation is
tracked by the approved [specification](../specs/4.5.0-production-recovery-orchestration.md),
[ADR-0044](../adr/ADR-0044-production-recovery-orchestration.md), and
[Gate checklist](../../tasks/todo.md).

No CI-only Evidence is considered PASS until its owning producer runs on the
exact merge. Local verification is useful implementation evidence, but cannot
be promoted into a release artifact or fabricated as a PASS value.

## Implemented scope

Implementation is complete through Gate F. Recovery Jobs provide durable
Component state, priority-aware bounded transfer, verified encrypted caching,
strongly bound Projection Plan reuse, bounded network/crypto/materialization
pipelining, renewable generationed holds, pause/resume/abort, capacity and
dependency preflight, bounded redacted telemetry, read-only DR readiness, and
an isolated manual Recovery Drill. Safe terminal paths release holds and pins;
partial or uncertain commits remain `recovery-required` and protected.

The Drill reuses the production fetch, decrypt, Merkle verification, and
materialization engine but cannot enter live federated prepare/commit. Focused
tests preserve a byte-identical live Workspace under success and injected
failure and scrub every known plaintext drill/staging path.

Prepared Object Sets remove object-set double compression. Payload readback is
skipped only after both single-part and multipart canaries prove authoritative
`FULL_OBJECT` SHA-256; ETag, metadata, missing, incorrect, or composite claims
fall back to full readback and fail closed before the commit marker on drift.

## Gate G evidence status

Two independent exact-merge CI producers are wired into Evidence assembly and
RC readiness:

- `object-set-s3-e2e`: real HTTP MinIO and the real Rust Age helper exercise
  cold selective recovery, warm recovery with zero remote Payload GETs, and a
  corrupt cache entry that refetches only the affected Payload.
- `recovery-fault-evidence`: real subprocess restart covers partial Component
  and pause/resume recovery; focused processes cover disk exhaustion, Hold CAS
  conflict, cache corruption, remote mutation, and partial federated commit.

The subprocess/fault matrix passes locally with the real Rust helper. That run
came from a dirty local source tree and is not release Evidence. The real MinIO
cold/warm path is CI-owned because Docker/MinIO is unavailable in the current
local environment. Frozen wire/legacy compatibility, the full repository gate
set, both CI producers, and exact-merge Evidence assembly remain required before
this document can say release-ready.

## Operations and monitoring

Before authorizing a live restore, inspect read-only preflight and readiness for
dependency availability, usable disk headroom, renewable Hold protection,
latest Drill outcome, actual RPO, and explicitly estimated RTO. During a job,
monitor phase/status, required versus fetched Components, cache hit/miss/
corruption, active and peak transfer concurrency/bytes, retries, integrity
failures, and Hold renewal generation. Treat a stale Drill, degraded protection,
capacity failure, integrity failure, remote mutation, or `recovery-required` as
a stop/rollback signal rather than forcing progress.

## Rollback and recovery boundary

4.5.0 does not migrate `object-set-v1`, Receipt v4, Commit v4, randomized Age,
Projection semantics, or legacy Whole-Age v2-v5. A deployment rollback can
return to the prior 4.4.15 application while preserving immutable encrypted
Target objects and receipts. Abort only when the durable phase proves no
participant committed; prepared-but-uncommitted transactions must be aborted
before cleanup. Any partial commit or uncertain participant state must remain
`recovery-required`, with holds and cache pins retained for operator recovery.
Never delete Target ciphertext or treat cache contents as a trust root during
rollback. Plaintext drill/staging roots are scrubbed; SSD physical secure erase
is outside the application guarantee.
