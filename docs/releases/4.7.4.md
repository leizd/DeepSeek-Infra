**适用版本：** v4.7.4

## 本版实现

4.7.4 把 4.7.3 的真实存储副作用升级为持久化、可审计、Evidence-closed
的自治运维层：

- 自治 proof 从目标 S3/MinIO 重新读取实际 Receipt v4 与 Commit v4 bytes，
  绑定 endpoint、bucket、object key、provider metadata、raw SHA-256、
  `Commit.receiptDigest` 与 `objectSetDigest`；synthetic digest 和 placeholder key
  无法通过 semantic validator。
- Storage Control Plane producer 同时上传 report 与 exact proof。report 保存
  proof path、SHA-256、byte size 和 scenario；producer staging 与 Evidence
  Assembly 会重新验证同一份 proof，缺失或篡改均 fail closed。
- 真实 crash gate 在 MinIO Repair 正处于 `transferring-components` 时硬终止
  Worker A。Worker B 只能在持久化 lease 过期后以更高 `executionEpoch`
  进入 `RECONCILING`，发现既有 `repairId`，且底层 Repair job 数保持为 1。
- global、target、policy 与 failure-domain admission 由两个独立 OS process
  对同一个 SQLite journal 竞争证明，每个 scope 都必须恰好一进一拒。
- exact RiskSubject 的 `OPEN/CLEARED/REOPENED` 生命周期持久化；Risk Debt
  使用 unresolved interval，而不是新生成 action 的年龄。Scheduler 将
  policy virtual runtime/finish、actions/bytes served 持久化并用于生产排序。
- Scheduler 将全部 candidate 分配到完整 DAG waves，或给出 typed
  `UNSCHEDULABLE` 原因；Repair reserve 由 `backup_transfer_budget` 强制执行，
  safe preemption 在同一事务中释放 victim lock/budget 并 claim critical Repair。
- Blast simulator 同时纳入 running effects 与 proposed actions。健康基线保持
  policy minimum；已经 degraded 的基线不得再减少 committed copy 或 failure
  domain。
- `.resilience-slo/slo.sqlite3` 持久化 risk detection/clear、queue delay、
  Repair/Rebalance、DR freshness、lease takeover、starvation 与 proof freshness；
  支持配置化 1h/24h burn rate、maintenance-window override，并通过鉴权的
  `GET /api/workspace/resilience/readiness` 提供 source-backed readiness。

本地真实三 MinIO developer run 已用于验证上述 autonomous proof 路径，但它
不是发布 Evidence。只有 exact-merge CI 的 Storage Control Plane artifact、
Evidence Assembly、95% coverage、offline eval 和 release gates 全部成功后，
才可宣称 4.7.4 release-ready。

运维与取证流程见
[Coordinated Autonomous Remediation runbook](../runbooks/COORDINATED_AUTONOMOUS_REMEDIATION.md)。

## 冻结合同

`object-set-v1`、Receipt v4、Commit v4、FastCDC v3、randomized Age、
Projection semantics、`control-authority-v1`、AuthorityCheckpoint v1 和
`dr-readiness-proof-v1` 保持不变。

## 明确不在本版范围

本版不引入 LLM 自治决策、自动 primary promotion、自动数据删除、自动降低
replication、Raft、multi-primary Authority、Receipt v5、Commit v5 或
`object-set-v2`。
