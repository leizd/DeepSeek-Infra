## 1. Executive Summary

DeepSeek Infra **4.5.8** converges the previously separate Repair,
Replication, Rebalance, Drain, Retirement, Capacity, and Transfer QoS
primitives into a restart-safe Storage Control Plane. The release preserves
the frozen `object-set-v1`, Receipt v4, Commit v4, FastCDC v3, Projection, and
randomized Age contracts while tightening lifecycle correctness around them.

The main invariant is that retiring a copy is a governed lifecycle event, not
an erasure of history. Formal Receipt and Commit bytes remain immutable;
authenticated Target-local retirement markers explain intentional payload
removal, and physical GC proceeds only when no live copy, hold, or active job
still references the ciphertext.

## 2. Hard Gates

### Gate A — Chain-Preserving Retirement

- `retirements/<policyId>/<backupId>.json` binds the Target, Policy, Backup,
  Receipt digest, Commit hash, object-set commitment, reason, and timestamp.
- Receipt v4 and Commit v4 remain byte-identical after retirement.
- Audit reports governed retirement separately from unmarked missing-object
  corruption.
- Payload GC is live-copy, hold, and active-job reference aware.

### Gate B — Durable Cross-Process Authority

- `.backup-control/control.sqlite3` is the CAS authority for Policy revisions,
  Target topology generations, promotion epochs, durable maintenance cursors,
  capacity observations, and shared transfer budgets.
- Mutations use SQLite transactions with `BEGIN IMMEDIATE`; two writers using
  the same expected revision cannot both commit.
- Policy and Target JSON files remain readable projections, not lock authority.

### Gate C — Logical-Point Placement and Capacity

- `minCommittedCopies`, `minFailureDomains`,
  `maxCopiesPerFailureDomain`, and `minRegions` are computed for one Logical
  Recovery Point rather than a Policy's historical copy count.
- Region and Failure Domain diversity are independent constraints.
- Matching RecoveryClass p90 restore evidence may make a topology-eligible
  Target RTO-ineligible; this remains an estimate (`isSla=false`).
- Operator-supplied storage and egress costs are evaluated after correctness,
  recoverability, diversity, capacity, and RTO.
- Unknown Force Full size is `capacityConfidence=unavailable`; bounded targets
  cannot pass admission using the removed fixed 500 MiB fallback.

### Gate D — Provider-Reconciled Multipart Resume

- Local multipart checkpoints are reconciled against provider `ListParts`.
- Equal state resumes; validated remote-ahead state advances the checkpoint;
  a missing upload restarts from zero.
- Part size or ETag conflicts abort and quarantine deterministically.

### Gate E — Managed Production Transfers

- P0 Restore, P1 Primary Publish, P2 Repair, P3 Required Replication, P4
  Scrub/Drill, P5 Rebalance/Drain, and P6 Best Effort wrap actual data streams.
- Every chunk consumes a shared global bucket plus independent source-read and
  destination-write buckets.
- Cross-process Disaster Recovery reservation shrinks background traffic when
  P0 work is active.

### Gate F — Durable Maintenance and Autonomous Drain

- `StorageMaintenanceSupervisor` advances recovery leases, replication,
  repair, rebalance, retirement, capacity probes, drains, and QoS state under
  cross-process leases with bounded work per tick.
- Drain uses durable keyset cursors and the production placement/capacity
  planner; histories larger than 500 Recovery Points remain covered.
- `drained` is blocked by live/unscanned copies, writer leases, active Backup
  Runs, Recovery/Restore/Drill holds, Repair/Rebalance source dependencies, and
  pending Retirement jobs.

### Gate G — Real Infrastructure Evidence

- `scripts/run_storage_control_plane_minio_e2e.py` owns the new exact-merge
  Evidence report.
- The CI producer starts three independent MinIO servers and uses boto3,
  `S3TargetStore`, production Policy/Scheduler/BackupExecutor/Maintenance
  Supervisor paths, and the real randomized Age helper.
- The scenario stops Target A, verifies formal failover and catch-up, repairs a
  real provider object, drains B into C, preserves B's formal history, commits
  a retirement marker, GCs payloads, and restores from A and C after subprocess
  restarts.
- Fake S3 and stub crypto cannot satisfy any real-Evidence check. The legacy
  replica runner no longer claims `realDualMinioE2EIntegration`.

## 3. Evidence Status

Local unit, integration-contract, lint, type, frontend, evaluation, security,
and release checks are reported separately from exact-merge infrastructure
Evidence. A local machine without Docker, boto3, three live MinIO endpoints, or
the real Age helper receives a FAIL report from the dedicated runner; a skipped
ordinary pytest node is never promoted to PASS.

The release is not represented as real-MinIO verified until the
`storage-control-plane-minio-e2e` CI producer succeeds on the exact release
revision and its provenance-bound report is assembled into the release
Evidence artifact. No artifact digest is claimed in this document.

## 4. Compatibility

- `object-set-v1`: frozen.
- Receipt v4 and Commit v4 wire formats: frozen.
- FastCDC v3: frozen.
- Randomized Age encryption: frozen; no plaintext fallback.
- Restore Projection semantics: frozen.
- Retirement markers and the SQLite control database are lifecycle/control
  metadata and do not alter Receipt or Commit wire formats.
