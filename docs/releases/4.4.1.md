# 4.4.1 — Crash-Safe Restore Transactions & Replica Fencing

中文标题：**崩溃安全的恢复事务与副本写入围栏**

4.4.1 把 4.4.0 的 Inspect/Apply 恢复升级为跨后端与浏览器的可恢复事务。恢复只有两个
稳定终态：完整成功，或完整回到恢复前；服务端已恢复而浏览器仍旧的状态不再被当成完成。

## 事务协议

1. `prepare` 创建 Safety Backup，把所有 Contributor 合并到独立 staging，并逐项验证。
2. 浏览器把 Head、Snapshot、Conflict Ledger、Index 与草稿写入全新的 Workspace Epoch；
   每个键都回读，来源 Writer、Lease 和 Revision 不复用。
3. 双方写入耐久 `commit-intent` 后，浏览器切换单一 `workspace.active-epoch` 指针。
4. 服务端使用目录交换提交完整 Contributor，双方核对摘要后 `complete` 并释放 Fence。
5. `commit`、`complete` 和 `abort` 幂等；响应丢失可以安全重试。

## 崩溃与旧标签页

- 服务端 Journal 在每个目录交换点前后落盘。启动时扫描中断事务：部分交换确定性回滚，
  完整交换保持 `backend-committed` 等待浏览器补发 Complete；损坏 Journal 进入
  `recovery-required`，不得猜测清理。
- 浏览器 Restore Journal 在启动时查询服务端状态并继续或切回 previous Epoch。
- 其他标签页收到 Fence 后立即取消自动保存和流式请求，不执行共享 Flush；未提交内容只写入
  previous Epoch Recovery Capsule，重新载入后作为恢复副本处理，不自动重放模型请求。

## Schema、屏障与传输

- Contributor 显式声明可迁移 Schema、身份字段、引用字段和受控路径字段。用户正文、Prompt、
  Skill 内容和 Artifact 正文不会因恰好包含旧 ID 而被修改；未来 Schema 会被拒绝。
- `.workspace-mutation.lock` 与耐久 Restore Fence 覆盖 Web、CLI 和后台写入口。备份通过
  generation 边界检测并发变化，变化时重试。
- 下载使用文件响应，上传从 Request stream 逐块写 staging、计算累计大小并在超限时立即中止；
  ZIP 展开继续按实际输出大小、条目数和压缩比限制。

## 保留策略

- `complete` 诊断记录保留 7 天，`rolled-back`/`failed` 保留 30 天。
- `recovery-required` 和活动 Restore 永不自动删除。
- Safety Backup 不随 Abort 删除；清理拒绝删除仍被 Fence 或 Journal 引用的事务。

## 无状态 MCP 执行平面

- 新增独立 `stateless-mcp/` 服务，使用官方 TypeScript SDK；每个 Streamable HTTP 请求创建新的 `McpServer`，实例不保存客户端会话。
- Redis 持久化测试任务、日志、租约、attempts、fencing token 与幂等索引。两个实例可在 NGINX 后轮询，owner 突然退出后由另一实例在租约到期时接管，旧 owner 不能迟到提交。
- 专用工具目录包含 `server_info`、`code_search`、`start_test_run`、`get_task` 与 `query_logs`。测试执行不接受任意 shell 字符串，路径限定在工作区，非幂等提交要求幂等键。
- OpenTelemetry 输出工具耗时与失败率；CI 的 `stateless-mcp`、`docker` 和 `stateless-mcp-failover` jobs 分别固定类型/单元合同、部署合同和容器级故障恢复合同。
- 默认 Python `/mcp` 的 17 工具、resources、prompts、Tool Policy 和 GUI 兼容性保持不变；专用执行平面不是其替代品。部署与演练见 [../STATELESS_MCP.md](../STATELESS_MCP.md)。

本版本不增加备份密码、云存储、自动/增量备份、多设备同步或运行中请求重放。密码加密备份与
恢复密钥管理留给 4.4.2。
