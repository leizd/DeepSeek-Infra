Release date: **2026-08-17**.

4.5.4 delivers **Autonomous Replica Healing & Backup Write Failover (自治副本修复与备份写入故障切换)**. It matures the replica self-healing architecture into a fully durable, restart-safe, bounded-streaming control plane and introduces automatic write failover when configured primary targets become unavailable.

## Highlights

1. **Durable Resumable Replica Repair State Machine (`ReplicaRepairJob`)**  
   Repairs are executed via a durable state machine (`queued` → `selecting-source` → `acquiring-source-hold` → `validating-source-control` → `scanning-destination` → `transferring-components` → `verifying-components` → `finalizing` → `healthy`). Per-component progress checkpoints allow process restarts to resume seamlessly without restarting transfers.

2. **In-Place Committed Copy Healing Contract**  
   When repairing missing or corrupted components for an already-committed recovery copy, the system repairs ciphertext objects in-place and preserves the original Receipt v4, Commit v4, `targetGeneration`, and `control/head.json` without emitting new control-plane commits.

3. **Bounded Streaming Ciphertext Transfers**  
   Component transfers stream ciphertext in bounded buffer chunks (8 MiB), limiting memory usage to $O(\text{buffer}\times\text{workers})$ and eliminating unbounded full-object in-memory buffering.

4. **CAS-Guarded Remote Corrupt-Object Replacement**  
   Corrupted objects on remote stores are inspected (`STAT` for ETag/VersionId), streamed to `.quarantine`, conditionally deleted, conditionally rewritten with known-good bytes, and verified against SHA-256 digests. Any CAS precondition conflict triggers fail-closed aborts.

5. **Target-Side Durable Protection Leases**  
   Replaces local-only source holds with durable, heartbeated protection leases stored directly on target stores (`holds/protection/` or `holds/repair/`), protecting active repair sources from concurrent retention deletion.

6. **Autonomous Bounded Reconciler**  
   Periodic background reconciliation runs under bounded limits (max policies, max recovery points, max concurrent transfers per tick) using persistent cursors.

7. **Two-Phase DR Remote Audit with Global Commit Chain Validation**  
   Paged remote scans stage unverified candidates without premature recovery point promotion. Global sorting by `targetGeneration` validates complete commit chain continuity, hash bindings, and `control/head.json` before atomic promotion to `recoverable`.

8. **Unified Retention Copy Safety Single Source of Truth**  
   Retention copy safety is derived directly from `policy.replication.minCommittedCopies` using canonical target identifiers across both filesystem and remote stores.

9. **Deterministic Backup Write Failover & Stability Failback**  
   Scheduled backup runs freeze Write Placement Plans in their `runPlanDigest`. When the primary target is unavailable, backups automatically switch to healthy Required Replicas, force Full snapshots (`write-target-failover`), and reuse single-encrypted spool packages. Failback to primary requires verified stability windows and replica convergence.

10. **DR Readiness Write Continuity Telemetry**  
    Readiness aggregation exposes `writeContinuity` telemetry, detailing active write targets, primary status, eligible failover targets, and failback eligibility.

## Compatibility

- Frozen wire formats: `object-set-v1`, Receipt v4, Commit v4, FastCDC v3, randomized Age encryption.
- Fully offline evaluation gates: RAG, Tool, Security Corpus, Injection Adversarial, and Agent Eval gates pass strictly.
