中文标题：**远程备份目标与条件对象存储**

4.4.5 把本地目标的提交围栏闭合之后，4.4.6 把同一套语义映射到 S3-compatible 对象存储：
条件写代替 `O_EXCL`，CAS Lease 代替 rename 抢锁，Commit Marker 仍是唯一可见性边界。

## 明确不做

- WebDAV / Google Drive / OneDrive / Dropbox GA
- 在 Target JSON、Policy、Journal、Receipt、Catalog、日志中保存 Access Key
- 远端故障时静默回退 `managed-local`
- 增量备份 / 内容级 dedupe（留给 4.4.7）
- 浏览器 presigned 直传、托管 Recovery Identity

## 证据合同

- `tests/test_backup_remote_target_contracts.py` 钉住 15 个 evidence key（见 `docs/EVIDENCE_INDEX.md` 的 `backup-remote-target-4.4.6`）。
- 既有 `tests/test_backup_fenced_commit_contracts.py` 继续作为 Filesystem adapter 对等性门禁。

## Target Store 协议

- `BackupTargetStore`：`put_if_absent` / `put_if_match` / multipart / range get / list。
- `FilesystemTargetStore` 完整承载 4.4.5 语义；`S3TargetStore` lazy-load boto3。
- Capability probe 必须通过 conditional-create + conditional-replace 才允许 Scheduled Backup。

## 远程发布与 Spool

- 布局：`objects/`、`receipts/`、`transactions/`、`commits/<policy>/<full-sha256>.json`、`catalog/head.json` + snapshots、`control/{identity,head,writer}.json`、`holds/restore/`。
- `.backup-spool/` 只存已验证 Age 密文；断网重试复用同一 ciphertext digest 并续传 multipart。
- 可见性仍只由 Slot Commit Marker 决定；Head CAS 失败由 Reconcile 前滚，不重新生成备份。

## 远程 Retention / Restore

- 逻辑 Trash 事件 + grace 后无引用 Physical GC；Restore Hold 保护进行中的下载。
- `POST /api/workspace/restores/from-target` 仅下载密文到本地 staging，随后复用既有 Unlock / Restore Transaction。

## 验收一句话

> 一个已经在本地验证完成的 Age 密文，可以在断网、Worker 接管、对象上传重试和并发提交的任意组合下，被安全、可恢复地发布到 S3-compatible Target；正式可见性仍只由唯一 Slot Commit 决定，云凭据与 Recovery Identity 永远不会进入备份元数据或持久化状态，远程恢复可以断点续传并最终完全复用现有联邦恢复事务。
