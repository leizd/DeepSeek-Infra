中文标题：**生产级增量备份与内容定义差分**

4.4.7 完成了增量基础设施；4.4.8 把它真正接进 Scheduler → Publish → Retention → Restore，并对大文件加入 FastCDC 内容定义差分。

## 增量生产化

- **Policy v2**：`incremental { mode: off|file-delta|cdc, maxChainDepth, fullIntervalDays, maxDeltaRatio, largeFileMode, largeFileThresholdBytes }`。v1 Policy 自动归一化为 `off`，不改变既有行为。
- **Run Plan 前选择 Snapshot Kind**：读取 Target Catalog + Snapshot Index，比较 Scope/Recipient/Schema，冻结 `snapshotKind/lineageId/parentBackupId/baseBackupId/chainDepth`；Retry 永不换 Parent。
- **强制 Full 条件**：chain depth、full interval、delta ratio、index 丢失、scope/schema/recipient 变化、Target Fork Adopt。Recipient Rotation 开启新 Lineage。
- **Receipt v3**：只暴露最小 Lineage（snapshotKind/lineageId/parent/base/chainDepth），`rootDigest` 留在 Age 内部 Manifest。
- **Snapshot Index**：`snapshot_lineages` / `snapshot_files` / `snapshot_chunks`，纯性能缓存，丢失即强制 Full。

## Content-Defined Deltas

- FastCDC `fastcdc-gear-v1`：min 512KiB / avg 2MiB / max 8MiB，Streaming、有界内存、确定性分块。
- 大文件变更只携带新 Chunk；边界扰动后重新同步，旧 Chunk 从 Parent 复用。
- Chunk 摘要只存在于加密包内 Manifest 与本地 Index，云端仍是随机 Age 密文 —— 不做 Convergent Encryption。

## 有效树与 DAG-aware Retention / Restore

- `diff_trees` 的 `rootDigest` 基于有效树（current + unavailable contributor 继承的父文件），Coverage Gap 是“继承”而非“消失”。
- Retention 保护所有被保留 Incremental 的祖先（`ancestor-of-kept-snapshot`），trashed-but-recoverable 后代仍保护其祖先。
- Restore Materializer 仅凭 Receipt Lineage 解析链，逐层应用 put/delete 并验证 Merkle Root；缺失 Parent / 损坏 Chunk 全部 Fail Closed。

## 明确不做

- Convergent Encryption / 确定性 Age / 云端明文 Chunk CAS / 跨 Target Chunk 去重 / Chunk 独立对象 / WAL 增量 / Incremental Safety Backup / WebDAV GA。
- 不允许 Parent Snapshot 被单独 Physical Delete。

## 证据

`tests/test_backup_448_contracts.py`：策略持久化、有效树继承、Snapshot Plan 选择、CDC 确定性/复用/有界内存、Receipt v3、DAG Retention、Materializer、Spool 复用、force-full 条件。

## 验收一句话

> Scheduler 不再永远生成 Full：已提交 Full Baseline 后，后续 Run 真正发布文件级 Incremental；大型变化文件只携带新的 CDC Chunk。任意 Incremental 都能仅依靠 Target 上的 Receipt + Age Packages + Recovery Identity，从 Full Ancestor 确定性重建并在每层通过 Merkle 校验；Retention 永不删除仍被任何可恢复后代依赖的祖先。
