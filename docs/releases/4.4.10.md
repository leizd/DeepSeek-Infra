中文标题：**流式增量恢复与原生差分加速**

4.4.9 证明了目标端只保存真实变化数据，也能沿 Full + Delta 链逐层恢复。4.4.10 把这条数据路径收紧成有界、可恢复、可并行且协议版本明确的生产闭环。

## 公开的远端恢复闭环

- `POST /api/workspace/restores/{restoreId}/materialize` 消费临时 Secret Slot，把远端 Chain 下载、解密、逐层应用并校验成完整 Workspace Tree。
- 已验证的 Tree 不建立第二套提交逻辑，而是直接进入既有 Federated Restore 的 Safety Backup、Frontend Epoch、Commit 与 Complete 状态机。
- Remote Session 持久记录 `fetching-chain → chain-fetched → decrypting-chain → materializing → verified → preparing → prepared → committing → complete`；重试复用同一 `restoreId` 并收敛。
- Secret 只存在短期 Vault；错误密码、缺层、摘要不符、计划不兼容均 Fail Closed。

## 有界流式重建

- Parent Range 与 Payload Chunk 均以最大 1 MiB 缓冲复制，不再调用 `Path.read_bytes()` 物化父文件或差分 Payload。
- 重建写入同目录临时文件；全部 Chunk、目标文件摘要和 Merkle 转移验证后才用原子替换提交。
- 父备份按 `(contributor_id, logical_path)` 复合索引查询 Chunk Map，避免为单个文件载入整份父快照索引。

## FastCDC v3 与双引擎合同

- 新写入协议固定为 `fastcdc-gear-v3`；`fastcdc-gear-v2` 解码器继续保留，显式 v2 Parent 升级时强制生成 Full Baseline。
- `BackupChunkEngine` 定义单次文件扫描结果：文件 SHA-256、逻辑字节数和连续 Chunk 边界/摘要。
- Python Engine 是权威兼容实现；`rust/crates/deepseek-backup` 提供同合同的原生实现。Native 缺失、启动失败或输出无效时安全回退 Python，绝不发布未经验证的结果。
- Parity 合同要求相同输入、协议与边界参数产生完全一致的 Offset、Length、Chunk SHA 和 File SHA。

## 自适应计划与受限并发

- `scanWorkers` 默认不超过 4；`maxInFlightBytes` 默认 64 MiB，同时约束排队文件的逻辑大小，避免 Worker 数量正确但内存仍无界。
- Builder 在一次遍历中完成文件哈希、CDC 边界和 Chunk 哈希，再从同一打开的源文件顺序写入变化 Payload。
- Candidate Delta 构建后按真实 `physicalPayloadBytes / logicalChangedBytes` 决定保留 Incremental 或以同一 Backup ID 重建 Full。
- 决策写入 schema v3 Run Plan 的 `plannedSnapshotKind`、`resolvedSnapshotKind` 与 `resolutionReason`；重试不得重新解释。

## S3 Multipart 恢复

- 新上传默认 4 个 Worker、16 MiB Part、64 MiB 最大在途字节；旧 Journal 没有 Part Size 时继续按 8 MiB 恢复。
- 每个 Part 完成后立即耐久写入 ETag/Part Number；恢复时先调用 `ListParts` 与服务端事实对账，再只上传缺失 Part。
- Submit、Part Completion 与 Complete Multipart 前均重新检查 Writer Lease/Fence；租约丢失立即停止，不让旧 Writer 完成对象。

## 可观测性和安全边界

- 报告 Scan Wall Time、Engine、Worker/Byte Budget、逻辑变化、物理 Payload、复用字节与节省比例。
- 遥测和远端 Receipt 不包含 Chunk SHA、文件正文、Recovery Identity、密码或云端 Access Key。
- 本版本不引入 Convergent Encryption、跨文件/跨备份 Chunk CAS、独立 Chunk S3 Objects、数据库 WAL 增量或 WebDAV。

## 验收一句话

> 一个大文件的小范围修改只生成局部 Payload；恢复时父文件与所有 Delta 都以有界窗口读取。Rust 与 Python 对同一文件产生完全相同的边界，实际 Delta 比率只冻结一次，S3 Multipart 在实例退出后从服务端已确认 Part 继续；最终恢复要么完整进入 Federated Restore，要么在正式 Workspace 改变前 Fail Closed。
