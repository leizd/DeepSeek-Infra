中文标题：**独立加密对象集与真正的选择性拉取**

4.4.14 先关闭 4.4.13 验收发现的三个 P0：Full 与 Incremental 必须拥有相同 Projection 语义；在 F0 后创建且存在于目标快照的 Project 必须可选恢复；Adaptive Full 不得把整个 Delta 明文归档驻留内存或在已超阈值后继续执行 Incremental Age 加密。前三个 Gate 与真实进程重启 Evidence 未通过前，不进入远端协议升级。

## Projection correctness

- Full 与 Incremental 统一为 `members → metadata decrypt → projection planner → selective extraction → projected materializer → federated restore`。
- 完整验证 F0→I1→…→In 的 root 后，从最终有效快照派生 Project 与 Contributor capability，再校验选择。
- 生产 Evidence 必须证明：选择 Project A 时，备份后继续分叉的未选 Contributor 从头到尾未被 Restore Transaction 覆盖。

## Adaptive memory safety

- Incremental 候选先流式写入有界临时归档，内存复杂度固定为 O(buffer)。
- `ThresholdWriter` 在超过 adaptive limit 时立即抛出 `DeltaCostExceeded`，终止 ZIP 生成并转入 Full。
- 只有未超阈值且已 fsync 的候选归档才允许进入 Age 流式加密。

## `object-set-v1`

新 Lineage 以 Force Full 开始。每个 Snapshot 由一个独立随机 Age 加密的 `control.age` 与若干独立随机 Age 加密的 Payload Components 组成：

```text
control.age
payload-0000.age
payload-0001.age
...
```

对象键始终只使用密文 SHA-256：`objects/sha256/<prefix>/<ciphertext-digest>.age`。禁止 plaintext-hash key、路径、Project 或 Contributor 名称进入远端键或 Receipt。

Control 解密后包含完整 Metadata Plane：Manifest、Payload Index、Component Map 与 Delta Operations。Plaintext SHA、Chunk SHA、Pack Role 与逻辑路径只能存在于加密 Control 内部。

## Independent randomized Age components

- 每个 Component 使用 fresh randomness 与相同 recipient set 独立加密。
- 相同明文 Component 在两次 Backup 中必须得到不同密文。
- 不引入 deterministic/convergent encryption，也不把 Age 改造成随机 Range Decrypt container。

## Receipt/Commit v4

Receipt v4 提交 `storageProtocol=object-set-v1`、`controlObjectDigest`、`objectSetDigest` 与排序后的密文对象摘要/大小集合。Commit Marker v4 绑定 Object Set、Control 与 Receipt 摘要；只有 Marker CAS 成功，Snapshot 才可见。

远端可观察的新增元数据只有 Component 数量与粗粒度密文大小。文件名、项目名、Contributor、plaintext SHA、Chunk SHA、Chunk equality 与 Component role 均不可见。

## Control-first selective restore

Restore 先获取并解密整条 Lineage 的 Control Objects，逐层验证 Metadata/Merkle root，然后计算：

```text
restoreOutputSet
restoreDependencySet
requiredComponentSet
```

只有 `requiredComponentSet` 可以触发 S3 GET。Preview 只下载 Control，返回整链密文字节、所需密文字节、网络节省比例、组件数及 Output/Dependency 聚合字节。

## Durable restart, spool and lifecycle

- Spool 保存精确密文路径、摘要、大小、上传状态与 `runPlanDigest`，Retry 必须重用相同 Component 密文。
- Restore Session 持久化 control/component fetch 状态，允许实际进程退出后继续下载、物化和 federated commit。
- Holds、Retention 与 GC 标记每个可恢复 Object Set 成员；未提交 Orphan 仅在 Grace 后回收。
- 缺少已提交 Component、外来 Component 或摘要不一致全部 Fail Closed。

## Compatibility

旧 Whole-Age v2-v5 Backup 永久可恢复。首次从 `whole-age-v1` 升级到 `object-set-v1` 必须以 `reason=storage-protocol-upgrade` 强制 Full，避免把 Whole-Age F0 留在 Selective Lineage 的基线。

## Explicit non-goals

本版本不做 Convergent/Deterministic Age、plaintext-hash S3 keys、跨 Backup/Policy/Target Chunk CAS、Immediate Parent 之外的历史引用、全局远端 Dedup、数据库 WAL 增量、WebDAV GA、Privacy Padding、Component Prefetch、并行 Selective Download、Local Encrypted Component Cache 或 Network-aware Auto Tuning。

## Release acceptance

> Full 与 Incremental Snapshot 必须拥有完全相同的 Projection 语义；任意在 F0 之后创建且存在于目标 Snapshot 的 Project 都必须可被选择恢复。Adaptive Full 不允许把整个 Delta 明文归档驻留内存，也不允许在已经确定超阈值后继续执行 Incremental Age 加密。新的 Object-Set Lineage 中，Restore 必须先只获取并解密 Control Metadata，再根据完整 Merkle-verified Dependency Closure 精确确定所需密文 Components；未选择且不属于 Dependency Closure 的 Payload Object 在整个恢复过程中不得发生一次 GET。所有 Component 独立随机 Age 加密，远端不得出现任何 plaintext hash/path/project metadata；旧 Whole-Age Backup 永久保持可恢复。
