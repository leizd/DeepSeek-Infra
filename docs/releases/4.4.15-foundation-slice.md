## Commit 2: `fix(restore): distinguish selective capability from actual network savings`

**Problem:** Full object-set restore (required == total) reported `networkSelective: true` — conflating protocol capability with actual network savings.

## Commit 3: `refactor(transport): introduce bounded component transfer scheduler`

**New file:** `deepseek_infra/infra/workspace/backup_component_transport.py` (198 lines)

Design:
- `SchedulerConfig` (frozen, embeddable in run plan for retry parity): `max_workers=4`, `max_in_flight_bytes=256 MiB`, `max_open_files=64`, `working_set_bytes=8 MiB`.
- `TransferTask`: component_id, ciphertext_digest, ciphertext_size, execute callable, working_set_bytes, priority.
- `TransferTelemetry`: thread-safe active/max_active/in_flight_bytes/max_in_flight_bytes/completed/failed counters.
- `ComponentTransferScheduler.run(tasks, cancel_event)`: ThreadPoolExecutor for worker bound; Condition-based byte-budget gate (not busy-wait); first error → set cancel, drain in-flight, re-raise; barrier semantics (caller's journal/commit fires only after run returns).
- Byte budget bounds the **transport working set** per worker (chunk buffers), not the full 64 MiB component size.

**New test file:** `tests/test_backup_component_transport.py` (215 lines, 9 tests):
- `test_scheduler_respects_max_workers` — instrumented active/max-active counters; asserts 2 ≤ max_active ≤ max_workers.
- `test_scheduler_respects_byte_budget` — 8 MiB working set, 16 MiB budget → max_active ≤ 2.
- `test_scheduler_barrier_propagates_first_error` — one task raises; scheduler re-raises; in-flight tasks drain.
- `test_scheduler_cancel_event_stops_new_tasks` — external cancel stops new tasks.
- `test_scheduler_empty_tasks_returns_clean_telemetry`.
- `test_scheduler_completion_order_is_independent` — varying delays, deterministic finished count.
- `test_scheduler_config_validates` / `byte_permits` / `as_dict`.

## Commit 4: `perf(publish): upload encrypted components concurrently`

**File:** `deepseek_infra/infra/workspace/backup_publish.py`

Change: replaced the serial `for component in package.components:` loop (`:566`) in `_publish_object_set_filesystem` with scheduler-based parallel execution.

- Extracted per-component body into `_publish_component(component)` closure.
- Each component → `TransferTask(execute=lambda c=component: _publish_component(c))`.
- `default_scheduler().run(upload_tasks)` — bounded parallel upload.
- **Journal barrier preserved**: `journal.update(phase="objects-published")` fires only after `scheduler.run()` returns (all components verified).
- **Crash semantics preserved**: crash mid-transfer leaves journal at `"started"`; restart re-verifies completed components via the `destination.is_file() and sha256==digest` branch (content-addressed cheap re-verify) and resumes incomplete ones.
- **Fencing preserved**: the publish operation holds the writer lease; individual tasks do not fence.
- **ObjectSetDigest unchanged**: it's a sorted commitment over ciphertext digests — completion order is irrelevant.
- `partials` list cleanup (except block) still works: `list.append` is GIL-atomic; `unlink(missing_ok=True)` handles already-renamed partials.
- Added `backup_component_transport` to the module imports.

**Parallelism safety root:** `object_set_digest(components)` = `sha256(sorted("digest:size\n" lines))`. Sorted = order-independent. Parallel completion cannot change the digest, the receipt, or the CAS commit.
