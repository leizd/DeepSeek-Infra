# DeepSeek Infra 4.3.6 — Cross-Tab Checkpoint Arbitration and Bounded Storage

<!-- docs-language-switcher:start -->
[中文](../../README.md) / [English](../../README.en.md)
<!-- docs-language-switcher:end -->

4.3.6 makes conversation persistence safe under multiple tabs and bounded under storage pressure. Conversation state is partitioned into per-conversation V3 shards, cross-tab commits are arbitrated by an exclusive Web Lock that can never let a stale tab overwrite, deletions commit tombstones before touching UI, current-conversation selection sinks into per-tab state, streaming saves are rate-bounded, quota exhaustion degrades deterministically, and page exits write recovery capsules that the next startup reconciles exactly once.

## Canonical release identity

- The root `VERSION` file remains the single release source of truth: CI derives evidence paths, artifact names and Docker tags from `RELEASE_VERSION`, and the `release-version` gate job runs first, enforcing cross-surface consistency through `scripts/check_release_version.py`.
- At release time `python scripts/check_release_version.py --require-release-note` additionally requires this note with a matching H1.

## Partitioned conversation checkpoints

- Conversation persistence moves from whole-store V2 snapshots to per-conversation V3 shards: `deepseek-infra.session.v3.head.<cid>` points at digest-verified `deepseek-infra.session.v3.snapshot.<cid>.<revision>` payloads, with revisions ordered as `<seq>.<tabId>` and linked through `parentRevision` chains.
- Editing one conversation serializes only that conversation; retention keeps the current and previous revisions plus any unresolved conflict, removes at most two shards per commit, and a budgeted idle orphan GC keeps cleanup O(1) regardless of save count.
- V2 generation journals migrate on the first verified V3 commit; legacy keys are deleted only after the new head verifies.

## Cross-tab arbitration and conflict recovery

- Conversation commits run inside an exclusive Web Lock (`deepseek-conversation-checkpoint`) with an equivalent lock-free sibling-detection fallback; the shared head is re-read inside the critical section, so a stale tab can never silently overwrite a newer revision.
- A losing branch is preserved as a per-conversation conflict copy (pointer `session.v3.conflict.<cid>`), recoverable from the notice bar (`查看最新` / `保留副本`) as an independent `（冲突副本）` conversation — never merged automatically.
- A `deepseek-conversation-sync` BroadcastChannel invalidates clean remote copies without ever switching the conversation a tab is viewing.

## Tombstoned conversation deletion

- Deleting a conversation commits a tombstone (`session.v3.tombstone.<cid>`) before touching UI state; a stale tab cannot resurrect the id — its edits survive only as a deterministic `（恢复副本）`.
- Tombstones are bounded (30 days / 50 entries) and are garbage-collected only after every live tab lease (`session.v3.tab.<tabId>`, five-minute staleness) has provably seen the deletion.

## Per-tab conversation selection

- The current-conversation selection is per-tab sessionStorage state; switching conversations never schedules a shared commit, and remote commits or deletions never move the conversation a tab is viewing.

## Streaming checkpoint backpressure

- Save scheduling coalesces normal edits over 300ms, throttles in-flight streaming to one commit per second with a trailing edge, and commits immediately on stream done/error/interrupted, deletion, page-hide and build-update activation — so long streams no longer hammer synchronous localStorage while terminal state is always durable.

## Bounded storage pressure

- Quota exhaustion degrades deterministically instead of failing: rebuildable `data:` image previews (≥1KB) are stripped first — names, types, sizes, fileIds and all text preserved — then oversized timeline raw payloads (>8KB) are capped, and every compaction records `{level, removedPreviewBytes, reason:"storage-pressure"}` on the checkpoint.
- User message bodies are never touched; a persistent failure keeps the old head and surfaces export/cleanup guidance instead of losing data.

## Uncommitted-tab recovery capsules

- Page exits write a synchronous per-tab recovery capsule (`session.v3.recovery.<tabId>`) for anything the normal flush could not commit.
- Startup reconciles each capsule inside the write lock exactly once: clean content commits in place, conflicting or tombstoned content returns as a deterministic `<cid>.recovered.<tabId>` copy, and crashed tabs' capsules are reclaimed once their lease is dead.

## Vendor runtime chunk

- The vendor runtime (react/react-dom/react-router/tanstack) splits into a separate cacheable core chunk via Vite `manualChunks`: the entry asset drops from 390KB to 157KB, the vendor hash survives app-only releases for immutable-asset caching, and bundle budgets are unchanged.

## Verification

- Frontend unit and contract tests (68 files / 567 tests) cover single-conversation shard serialization, O(1) checkpoint cleanup, in-lock head re-read against stale writers, conflict-copy recovery, tombstone resurrection prevention, per-tab selection independence, 1Hz streaming backpressure, two-level quota degradation with compaction metadata, and exactly-once capsule reconciliation.
- The real Chromium smoke adds ten cross-tab evidence keys — `crossTabDisjointWritesPreserved`, `sameConversationConflictDetected`, `staleWriterCannotAdvanceHead`, `deletedConversationNotResurrected`, `tabSelectionRemainsIndependent`, `checkpointCleanupRemainsConstantTime`, `streamCheckpointRateBounded`, `storagePressureCompactionLossless`, `recoveryCapsuleReconciledOnce`, `conflictBranchRecoverable` — gated by a preflight `>= (4,3,6)` version check; the full run passed locally twice (120/120 checks).
- Bundle budgets are unchanged: initial JS ≤ 390,000 bytes, initial CSS ≤ 28,000 bytes, optional chunk ≤ 90,000 bytes.

The backend API, Provider ownership, dependency surface and offline Mutation-persistence contracts are unchanged; bundle budgets hold even though the vendor runtime now ships as a separate cacheable core chunk. 4.3.6 deliberately excludes raw File persistence, an offline mutation queue, automatic replay of chat/agent requests, any third-party state-management or database library, backend protocol changes, bundle/CSS budget increases, automatic merging of conflict branches and forcing other tabs to close or reload.
