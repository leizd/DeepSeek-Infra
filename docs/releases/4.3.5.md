# DeepSeek Infra 4.3.5 — Durable Checkpoints and Recovery Integrity

<!-- docs-language-switcher:start -->
[中文](../../README.md) / [English](../../README.en.md)
<!-- docs-language-switcher:end -->

4.3.5 makes every frontend checkpoint durable, diagnosable and honestly recoverable. The release identity converges on one canonical source, persistence flushes report per-source outcomes, Composer drafts migrate losslessly, conversation state commits as a journaled snapshot/verify/head transaction, interrupted generations and agent runs recover without replaying paid work, and BFCache restores resynchronize the runtime in place.

## Canonical release identity

- The root `VERSION` file is the single release source of truth: CI derives evidence paths, artifact names and Docker tags from `RELEASE_VERSION`, and the `release-version` gate job runs first, enforcing cross-surface consistency through `scripts/check_release_version.py`.
- At release time `python scripts/check_release_version.py --require-release-note` additionally requires this note with a matching H1.

## Diagnosable flush outcomes

- Persistence flushers report per-source outcomes with reason codes (`quota-exceeded` / `storage-unavailable` / `verification-failed` / `unknown`) instead of one opaque failure.
- `beforeunload` blocks exit when a flush has just failed, even without active blockers; `pagehide` records the failure together with the last successful revision.
- The update banner names the failing source (`对话记录保存失败` / `草稿保存失败`) and offers a `重新保存` retry action.

## Lossless composer drafts

- Legacy draft migration writes and verifies the scoped key before deleting the old one, so a failed or torn migration never loses text.
- An in-memory draft repository retains drafts across conversation and project switches even when sessionStorage writes fail, and stale-scope saves can no longer overwrite the active scope.

## Journaled conversation checkpoints

- Conversation state commits as a generation journal: `deepseek-infra.session.v2.snapshot.<N>` is written and verified before `.head` advances, retaining generations N and N-1.
- Legacy keys are deleted only after a verified commit; a corrupt head falls back to N-1, and failures record a byte estimate and reason.

## Honest interruption recovery

- Generations killed by a page close or refresh reload as honestly `interrupted`, preserving partial content and reasoning with the note `页面关闭或刷新时生成被中断。` and a `继续生成` action instead of masquerading as in-flight.
- Agent runs reconcile against server status on restore: active runs re-attach from their cursor, terminal runs settle, missing runs settle as interrupted, and unreachable servers mark the run `orphaned` with a `恢复 Agent Run` action — never replaying requests or re-spending tokens.

## BFCache runtime resync

- A `pageshow.persisted` restore retries failed persistence, forces a build re-check, re-handshakes the service worker, re-reports the page build lease and resumes dead timers — without duplicating listeners, channels or intervals.
- BFCache resync never auto-reloads, never activates a waiting worker and never resumes paid model requests.

## Verification

- Frontend unit and contract tests (62 files / 452 tests) cover flush outcome attribution, `beforeunload` blocking on a failed flush, verify-then-delete legacy migration, cross-scope in-memory drafts, generation-journal atomic commit and fallback, honest interruption recovery, Agent Run reconciliation without replay and single-flight BFCache resync registration.
- The real Chromium smoke adds ten durable-checkpoint evidence keys — `canonicalReleaseVersion`, `flushFailureIdentified`, `beforeUnloadBlocksFailedFlush`, `legacyDraftMigrationLossless`, `scopeSwitchDraftRetained`, `conversationCheckpointAtomic`, `checkpointFallbackRecovered`, `interruptedStreamRecoveredHonestly`, `agentRunReconciledWithoutReplay`, `bfcacheRuntimeResynchronized` — gated by a preflight `>= (4,3,5)` version check; the full run passed locally (110/110 checks).
- Bundle budgets are unchanged: initial JS ≤ 390,000 bytes, initial CSS ≤ 28,000 bytes, optional chunk ≤ 90,000 bytes.
