# DeepSeek Infra 4.3.7 — Replica Convergence and Durable Conflict Resolution

4.3.7 closes the remaining multi-tab persistence gaps from 4.3.6. Conflict branches remain isolated until an explicit user decision, every concurrent loser has a durable ledger entry, copy resolution commits before releasing its source, lock-free writers converge through immutable proposals, corrupt Heads self-heal, stale tabs cannot resurrect missing ids, and Recovery Capsule V2 verifies every payload.

## Durable isolated conflicts

- A conflict creates `deepseek-infra.session.v3.conflict.<cid>.<conflictId>` plus an indexed `conflict-index.<cid>` entry.
- Continued editing advances only `branchRevision` and `parentBranchRevision`; the shared Head is never used as an implicit rebase.
- All pending branches and their chains remain protected from retention and idle GC. The notice shows the pending count and resolves one branch at a time.

## Transactional resolution

- “Keep copy” uses a stable copy id, commits and digest-verifies an independent Head, reloads it, then marks and removes only the selected ledger entry.
- A failed snapshot, Head or release marker leaves the original branch protected. Retrying after a crash converges on the existing copy without creating duplicates.
- “View latest” validates and adopts the shared Head before marking only the selected branch discarded.

## Replica identity and lock-free convergence

- `tabContinuityId` is selection-only; each real Document receives UUID `writerSessionId` and `documentInstanceId` values.
- Revisions, leases, conflict records and recovery capsules use the writer UUID. BroadcastChannel `writer_claim` / `writer_claim_ack` messages rotate duplicate writers without changing selection continuity.
- When Web Locks are unavailable, writers create unique snapshot/proposal records, enumerate valid siblings for the same parent, and choose a deterministic winner. Losing snapshots enter the conflict ledger.
- The lock wrapper distinguishes lock-system failure from a callback that already started; callback exceptions propagate and the transaction is never rerun.

## Self-healing history and Recovery Capsule V2

- Loading a corrupt advertised Head records the actual valid parent revision as the local base. Exclusive arbitration repairs the Head if it is unchanged and records a quarantine marker.
- A local non-null base with a missing shared Head is treated as deletion/reset even after tombstone GC; the old id cannot be recreated.
- Capsule V2 stores per-entry and whole-capsule digests, sequence and writer identity, verifies write-back bytes, deterministically strips rebuildable previews under quota pressure, preserves every message body, quarantines invalid records, and writes a resolved marker before deletion.
