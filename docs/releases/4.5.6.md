Release date: **2026-08-17**.

4.5.6 delivers **Transactional Write Failover & Failure-Domain Rebalancing (事务化写故障切换与故障域副本重平衡)**. It closes the production loop by wiring failover directly into `BackupExecutor` publish operations under formal commit reconciliation, incremental parent lineage verification, invariant preservation, and failure-domain-aware replica placement and online rebalancing.

## Highlights

1. **Transactional Publication Failover in `BackupExecutor`**  
   Publish failures on the active write target automatically invoke transactional failover. Probes determine the primary target's commit state: if commit succeeded, the run converges immediately; if absent, the run transitions to an eligible candidate replica without re-snapshotting, re-packing, or re-encrypting (Zero Re-snapshot & Zero Re-encrypt); if indeterminate, the execution safely enters `ambiguous-write`.

2. **Incremental Parent Lineage Eligibility Verification**  
   Incremental backup packages enforce parent lineage presence before allowing failover. A candidate replica must possess an authenticated, committed copy of the required `parentBackupId`. If missing, failover is safely blocked, causing the run to fail gracefully so that subsequent scheduler cycles trigger a forced full backup.

3. **Autonomous Reverse Catch-up Repair (`B -> A`)**  
   When a failover write occurs on replica B, the background reconciler detects that recovered primary A is missing the new Recovery Point. The reconciler automatically provisions and authenticates the committed copy from B to A via bounded multipart ciphertext streaming without decrypting.

4. **Governed Primary Failback**  
   Failback to the configured primary target requires continuous health over a configurable stability window (>=1800s) and verified convergence of the latest exact Recovery Point on the primary target.

5. **Failure-Domain Aware Placement Engine**  
   Policy schemas and candidate selection algorithms incorporate `minFailureDomains` and `maxCopiesPerFailureDomain`. Placement ranking optimizes for protocol capabilities, fresh liveness, parent lineage availability, failure-domain diversity gain, replica lag, priority, and cost class.

6. **Durable Online Replica Rebalancing (`ReplicaRebalanceJob`)**  
   Introduces persistent rebalance jobs for re-aligning copy topology to updated policy constraints. Executes copy provisioning with strict minimum healthy copy preservation and zero Age decryption/re-encryption.

7. **Target Drain Lifecycle Management**  
   Implements structured drain states (`active -> draining -> drained`) with HTTP governance endpoints (`POST /api/workspace/backup-targets/{targetId}/drain` and `activate`). Draining targets are excluded from write placement and safely evacuated during rebalancing.

8. **Bounded Streaming Remote Object Quarantine**  
   Quarantine and replacement of corrupted remote objects use bounded chunked streaming, eliminating high-memory buffering and enforcing cryptographic verification across all storage operations.

## Compatibility

- Frozen wire formats: `object-set-v1`, Receipt v4, Commit v4, FastCDC v3, randomized Age encryption.
- Fully offline evaluation gates: RAG, Tool, Security Corpus, Injection Adversarial, and Agent Eval gates pass strictly.
