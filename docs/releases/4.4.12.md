# 4.4.12 — Packed Delta Payloads & Persistent Snapshot State

中文标题：**差分负载打包与持久化快照状态**

4.4.11 让 Immediate Parent 的 Chunk 和整文件可以安全复用。4.4.12 处理去重生效后的规模瓶颈：Incremental Index 只随变化量增长，新 Payload 直接进入少量 Pack，而不是重新复制完整 Effective View 或制造成千上万个 staging/ZIP Blob。

## Index v3：Delta State + Current Effective View

- `file_versions` 以文件大小、文件 SHA-256 与可选 Chunk Map 内容寻址；Copy/Rename 可以共享同一个不可变版本。
- Full 的 `snapshot_file_ops` 是完整 PUT Checkpoint；Incremental 只记录发生变化的 PUT/DELETE。
- `current_effective_files` 只保存最新 Immediate Parent 的 Path→Version；`current_effective_heads` 用单行 generation/root 指针证明它与最新 committed snapshot 一致，避免每轮重写所有文件行。
- Lineage、Chunk Map、File Version、Snapshot Ops、Current View 与 Head 在同一个 `BEGIN IMMEDIATE` 事务中提交。任何迁移、Head 或 Root 不一致都会耐久标记 stale 并 Force Full。
- 历史 Snapshot 由 Full + 有界 Delta 重放；Retention 物理删除后再清理无引用 File Version/Chunk Map。Scheduler Critical Path 不执行完整 `VACUUM`。

## Incremental v5：Snapshot-local Packfile

- Pack 目标 64 MiB、最大 72 MiB、8 字节对齐。CDC 新 Payload 始终 Pack；不超过 16 MiB 的 Whole Payload Pack；更大的 Whole Payload 保持 typed standalone。
- `payload/packs/index.json` 和所有 Blob/Pack Hash 均留在 Age 内部，不进入 Receipt、Catalog、S3 Metadata 或遥测。
- Pack 只组织当前 Snapshot 自己的新 Payload，不引用其他历史 Snapshot，也不新增 Retention Dependency Edge。
- Packing Metrics 只报告 Blob/Pack 数、字节与避免的文件/ZIP Entry 数，不包含 Path 或 Hash。

## Range Restore 与分层完整性

- Materializer 通过统一 Payload Source 读取 Standalone、Pack Range、Parent Range 与 Parent File。
- Pack Range 先验证 Pack SHA-256，再验证 Offset/Length/Blob SHA-256；重建后继续验证 File SHA-256 与 Snapshot Merkle Root。
- Pack Path、Index 类型、整数范围与边界全部按不可信输入验证；最多缓存 4 个只读 Pack Handle。
- Incremental v2/v3/v4 永久兼容；v5 不改变 `fastcdc-gear-v3`，因此 4.4.11 Parent 可以直接生成 v5 Child，不强制 Full。

## Persistent Native Scanner

- Python 使用持久 `Popen` JSONL Helper，不再为每批调用 `subprocess.run(...capture_output=True)`。
- Rust 通过受控 Worker Pool 并行扫描，并在单文件完成时立即输出带 Request ID 的结果；单项失败仍只回退该文件。
- Worker 数由 `workers` 和 Working-set Budget 共同限制。Working Set 按 CDC 最大 Chunk、Reader Buffer 与 Metadata Budget 估算，不再把 50 GiB 文件当成 50 GiB 内存占用。

## Scale 与真实 S3 合同

- 20 万文件、每轮几十个变化时，新增 Index Row 必须近似与变化量成正比。
- 10 万个 Tiny Payload 不得生成 10 万个 Payload/ZIP Entry，而应收敛为少量 Pack。
- CI 通过真实 HTTP S3-compatible 服务验证 Full、Packed Incremental、Multipart Resume 与 v5 Restore 的字节级一致性。

## 明确边界

本版本不引入云端 Chunk CAS、Convergent Encryption、跨 Policy/Target 去重、Immediate Parent 之外的历史引用、独立 Chunk S3 Objects、数据库 WAL 增量或 WebDAV。Pack 与 Index Maintenance 只能影响性能和空间，不能改变 Snapshot、Merkle 或 Commit 正确性。

## 验收一句话

> 当一个 20 万文件 Workspace 每轮只变化几十个文件时，本地 Index 新增状态只随变化量增长；当一次 Delta 产生数万个小 Blob 时，它们被流式写入少量加密 Pack。所有 Pack Range 独立校验，旧 incremental-v2～v4 永久可恢复，任何 Pack/Index/Compaction 故障只能降低性能或强制 Full，不能损坏已提交备份。
