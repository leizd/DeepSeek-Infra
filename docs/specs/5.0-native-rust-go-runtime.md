## Assumptions accepted from the user direction

1. "Complete Rust/Go transformation" means zero Python in every production
   runtime and distributable, including server, desktop, Android, document/OCR,
   media, MCP, and background-worker paths.
2. Python may remain in the repository only for offline evaluation, canonical
   reference oracles, migration/release tooling, benchmarks, and compatibility
   fixtures. Those files must not be present in or required by production images.
3. TypeScript remains authoritative only for the browser frontend. Existing
   production TypeScript services, including the stateless MCP plane, require a
   Rust/Go replacement or an explicitly approved deprecation before 5.0.
4. 4.8.1 is a contract-freeze release. It adds no product capability and does
   not take production mutation authority away from Python.
5. The migration is incremental and evidence-gated. It is not a file-by-file
   translation and it is not a big-bang rewrite.

## Objective

Move all production traffic, durable state, side effects, and safety decisions
from the Python-first 4.x runtime into a native Rust data/security plane and Go
control plane without changing established public or storage wire semantics.

The end state serves operators and clients through one Rust listener, uses Go
for desired/actual state reconciliation, and uses Rust workers for byte movement,
cryptography, protocol validation, retrieval hot paths, and sandboxed execution.

Success is defined by ownership, not source-file percentages:

```text
Frontend TypeScript
        |
        | public HTTP/SSE
        v
Rust edge/data/security plane
        |
        | versioned gRPC/Protobuf
        v
Go control plane  ---- commands ---->  Rust workers
        ^                                  |
        +---------- results/proofs --------+
```

## Production ownership matrix

### Rust: data plane and security plane

Rust is the sole production owner of:

- Public listener, LLM gateway, SSE streaming, authentication enforcement,
  request bounds, rate limiting, backpressure, timeouts, and tracing entry.
- MCP JSON-RPC validation/routing and production tool execution sandbox.
- Deterministic URL, path, capability, and safety-policy primitives.
- RAG normalization, tokenization, scoring, vector hot paths, and native
  replacements for any production document/OCR/media path retained in 5.0.
- FastCDC, chunk pipelines, randomized Age encryption/decryption, Ed25519 key
  custody/signing, S3/MinIO streaming transfer, backup/restore byte movement,
  federation ciphertext transfer, and proof cryptographic verification.
- Canonical object-set, Receipt, Commit, federation-document, and Evidence
  validation at the byte/security boundary.
- Rust-local transfer job checkpoints and the data-plane effect journal.

### Go: control plane

Go is the sole production owner of:

- Configuration, process lifecycle, health/readiness, and `/api/*` control APIs.
- Policy/target registries and all desired/actual state.
- Backup scheduling, Agent DAG scheduling, jobs, leases, fencing, action journal,
  waves, risk lifecycle, capacity/forecast loops, maintenance, resilience, and
  disaster-recovery orchestration.
- Federation peer/trust/grant/session lifecycle, transfer control journal, and
  durability objectives. Private signing keys never enter the Go heap.
- Go-owned durable control-plane tables and schema migrations.

### Python and TypeScript after cutover

Python is never allowed to serve production HTTP, own a production database,
schedule or execute production actions, move production storage bytes, hold
production private keys, or decide production safety outcomes. Browser
TypeScript remains a client only; it owns no server-side production effect.

Every existing production feature must reach one of two explicit outcomes before
5.0: native parity or approved deprecation with consumer migration. No feature is
silently dropped because its current implementation is ecosystem-heavy Python or
server-side TypeScript.

## Internal contract

All new Go/Rust process boundaries use versioned Protobuf messages and gRPC.
Ad-hoc JSON compatibility bridges and C/cgo/FFI are not the primary architecture.

```text
proto/
  common/v1/
  control/v1/
  action/v1/
  storage/v1/
  federation/v1/
  evidence/v1/
  agent/v1/
```

Every mutation command, result, effect, and proof carries the exact pair:

```text
actionId + executionEpoch
```

The pair must remain bound through Go scheduling, the Go Action Journal, Rust
RPC admission, the Rust effect journal, provider metadata, Receipt/Commit/proof,
and Go reconciliation. Only the authoritative Go claim/takeover transaction may
establish or advance the live epoch. Effect admission is read-only and requires
the command epoch to equal the locally resolved live epoch exactly: a lower epoch
returns `STALE_EXECUTION_EPOCH`, while an absent authority record or a future
epoch presented directly to an effect path returns `FENCE_MISMATCH`. A worker
must not trust a caller-supplied `live_epoch` assertion or mutate its live epoch
as a side effect of admission. An absent, malformed, or unrecognized effect
outcome is `EFFECT_UNKNOWN`; it is never interpreted as not-applied and never
authorizes a replacement side effect.

Proto evolution is additive within a `v1` package. Field numbers and enum values
are never reused. Unknown fields must survive compatible relays where the chosen
runtime supports preservation. Boundary validators reject zero/empty identity,
zero epochs, unsupported schema versions, digest mismatches, and invalid state
combinations before business logic runs.

`proto/generated/descriptor.v1.json` is the immutable semantic baseline for the
initial `v1` freeze; normal code generation cannot rewrite it. The release gate
does not parse Proto source text with regular expressions. It reads the complete
`FileDescriptorSet` from `proto/generated/descriptor.pb` with the checksum-pinned
Python Protobuf validator, then compares field identity/type/cardinality, JSON
name, oneof membership, proto3 presence, relevant options, enum values, service
methods, RPC types, streaming shape, and RPC options against the baseline.
Removals or reinterpretations fail closed while additive extensions remain
possible. The same `descriptor.pb` is the single binary descriptor used for
generated bindings. Rust's protox build must reproduce those exact protoc bytes
before Tonic code is compiled.

The repository pins Go 1.27.1 and protoc 36.1 in a machine-readable toolchain
lock. Both are current stable releases as of this specification. Exact compiler,
plugin, and runtime versions plus Windows/Linux archive checksums are committed;
the Python Protobuf 7.35.1 descriptor validator is installed from one exact
cross-platform wheel URL and SHA-256. Generated Go bindings, Rust Prost/Tonic
types, and descriptor drift are CI failures. The native CI jobs install the
checksum-pinned artifacts directly, set `GOTOOLCHAIN=local`, and use Cargo with
`--locked`, including coverage measurement and test inventory; implicit toolchain
or dependency resolution is not accepted as release evidence.

Official sources:

- https://go.dev/doc/devel/release
- https://protobuf.dev/support/version-support/
- https://protobuf.dev/support/cross-version-runtime-guarantee/
- https://pypi.org/project/protobuf/7.35.1/

## Durable state ownership

The invariant is **one table, one authoritative writer**.

| Durable state | Sole owner | Cross-plane representation |
| --- | --- | --- |
| Policy, target metadata, scheduler, Action Journal | Go | command/event/result/proof |
| Risk, wave, capacity, forecast, maintenance | Go | command/event/result/proof |
| Federation control/trust/grants/sessions | Go | signed request/result/proof |
| Transfer jobs, local worker checkpoints | Rust | result/progress/proof |
| Data-plane effect journal | Rust | effect result and reconciliation query |
| Frozen Python 4.8.0 state | Python oracle only | canonical fixture, never shared writes |

Python, Go, and Rust must never write the same SQLite database or table. Shadow
evaluation writes only to isolated shadow stores or immutable comparison output.
Cutover uses export/import plus ownership fencing, never cross-runtime dual-write
to one authoritative table.

## Frozen compatibility surface

Migration must not revise or reinterpret:

- `object-set-v1`
- Receipt v4
- Commit v4
- FastCDC v3
- randomized Age semantics
- `control-authority-v1`
- AuthorityCheckpoint v1
- `dr-readiness-proof-v1`
- `evidence-proof-v2`
- `predictive-planning-proof-v1`
- signed Federation 4.8.0 document and trust semantics
- existing public REST, SSE, MCP, and A2A wire behavior unless a separate,
  approved deprecation contract explicitly changes it

Parity is semantic and byte-exact wherever the existing contract is canonical.
Passing language-local unit tests is not release evidence.

## Release sequence and cutover rules

### 4.8.1: Native Runtime Contract Freeze

- Freeze Python 4.8.0 behavior into canonical HTTP/SSE/MCP/A2A, storage,
  federation, evidence, error, and state-transition corpora.
- Accept ADR-0049 and publish the unique ownership matrix.
- Add versioned Proto sources, reproducible generation, Rust and Go bindings,
  compatibility replay harnesses, and generated-code drift checks.
- Add `deepseekd` read-only/shadow lifecycle and Rust worker-protocol foundation.
- Python retains every production mutation authority in this release.

### 4.9.0: Go Control Plane Foundation

- Run isolated Go shadow state and compare deterministic decision digests.
- No Go production mutation until exact corpus and live shadow parity gates pass.

### 4.9.1: Rust Storage and Transfer Plane

- Move backup, repair, rebalance, restore, and federation payload bytes to Rust.
- Go issues fenced commands; Rust returns Receipt/Commit/effect proof.
- Python never observes production payload bytes after this gate.

### 4.9.2: Rust Edge Authority

- Rust becomes the single public listener and owns all fast/data endpoints.
- `/api/*` is internally proxied to Go; users continue to see one port.

### 4.9.3: Go Full Control Authority

- Cut control domains through shadow -> dual-evaluate -> Go-authoritative ->
  Python-shadow -> Python-disabled, one domain and one durable store at a time.

### 4.9.4: Python De-authoritization

- Default deployment is Rust edge + Go controller + Rust workers + static UI.
- Python compatibility is opt-in rollback only and receives zero production
  requests, mutations, schedules, storage writes, and signatures.

### 5.0.0: Native Rust/Go Runtime

- Production images and distributables contain no Python interpreter/runtime.
- Legacy Python production fallback is removed. Offline repository Python stays.
- All feature-parity, native failure-recovery, security, performance, and real
  provider-backed evidence gates pass on the exact release head.

## Code style

Proto field names use snake_case; generated Go/Rust names are accepted without
adapter renaming. IDs and digests remain strings at the wire boundary but are
validated into strong internal types. Enums always reserve zero for unspecified.

```protobuf
syntax = "proto3";

package deepseek.action.v1;

message ActionFence {
  string action_id = 1;
  uint64 execution_epoch = 2;
}

enum EffectState {
  EFFECT_STATE_UNSPECIFIED = 0;
  EFFECT_STATE_NOT_APPLIED = 1;
  EFFECT_STATE_APPLIED = 2;
  EFFECT_STATE_UNKNOWN = 3;
}
```

Go control code favors explicit state machines, contexts, bounded goroutines,
and transactional store interfaces. Rust data code favors validated newtypes,
bounded streaming, explicit error enums, no unsafe code without a separate ADR,
and zero secret-bearing debug output.

## Testing strategy

- Small: Proto validation, action/epoch binding, state transitions, deterministic
  decision digests, canonical encoding, bounds, and error-category parity.
- Medium: real local Go/Rust processes over gRPC, isolated stores, public-route
  replay, stale-epoch rejection, crash/restart, and generated-code drift.
- Large: native edge/controller/worker topology, real provider storage, process
  SIGKILL/takeover, federation recovery, no duplicate effect, and release images.
- Fuzz: Proto boundary validators, scheduler/journal/grant/federation sequences,
  MCP, object-set, Receipt, Commit, attestations, and proof validators.
- Performance: cold start, idle RSS, gateway p50/p99 overhead, bounded SSE memory,
  O(chunk) backup memory, zero full-buffer 1 GiB transfer, and 10k-action bounded
  reconciliation latency.

Canonical parity gates compare normalized wire bytes/digests, stable error codes,
ordering, state transitions, and remote side-effect identity. Real Three-MinIO
and native federation evidence is mandatory for storage/control release claims.

## Boundaries

- Always: preserve unrelated worktree content; fail closed on unknown effects;
  bind action ID and epoch end to end; validate at process boundaries; keep one
  authoritative owner per durable table; use exact-head evidence for release.
- Ask first: changing a frozen public/storage/federation contract; dropping a
  production feature instead of porting it; changing auth semantics; adding an
  unsafe/FFI boundary; changing real provider topology or secret handling.
- Never: big-bang rewrite; shared cross-language SQLite writes; permanent Python
  fallback; main-architecture cgo/FFI; ad-hoc internal JSON RPC; fake provider
  evidence; manual proof-ledger writes; constant-zero migration counters; silent
  fallback after an uncertain remote effect; merge automatically.

## Desktop platform window boundary

The native `deepseek-launch` supervisor starts `deepseek-desktop` by default;
`--server` selects the headless path. The platform host loads the retained React
frontend from the Rust public listener, exchanges the existing private launch
URL for the gateway's HttpOnly cookie, and retains its browser profile under the
isolated data root. Its environment contains only OS directory variables, that
URL and its profile path. Provider keys, control credentials and execution
authority stay in the backend. The production WebView2 host disables host web
messages and developer tools, retains system permission prompts, and installs
no JavaScript business bridge. Business/state requests still use public HTTP;
Rust/Go internal ownership and versioned gRPC contracts remain unchanged.

Windows uses the checksum-pinned Go module `github.com/wailsapp/go-webview2`
`v1.0.23` core SDK with `CGO_ENABLED=0` and the installed Microsoft WebView2
Runtime. Children join a private Windows job while suspended; closing its last
handle kills backend, desktop and browser descendants. A normal window close
stops the supervisor successfully; a failed UI child retains a failing exit.
The supervisor's URL helper is independent of the platform host, so headless
launch does not initialise WebView2 COM. A control startup waits at most 35 seconds
for an existing writer to release or expire, using the unchanged durable claim.
No fence is reset or lease deleted. The desktop checks the existing authenticated
`/api/control/status` route through the Rust gateway, with a 40-second readiness
budget; an independently served static document or Rust configuration response
cannot prove the Go writer is ready. Window message-loop errors reach the caller.
The actual Windows SDK workload and default-launcher hard-kill receipts are
recorded in the continuation. Linux/macOS host implementations and process
fencing, configuration/mobile launch flows, startup-error UI and distributable
upgrade qualification remain open; this section is a boundary contract, not a
whole-platform or release readiness claim.

## Android platform decoding boundary

`proto/platform/v1/ocr.proto` defines a read-only `PlatformOcrEngine` service:
image/PDF recognition and PDF page rendering. The Android glue invokes platform
bitmap/PDF APIs and bundled ML Kit inference; Rust owns document normalization,
candidate scoring, page mapping, upload cache, reader/search and product state.
The engine never receives product paths, action authority, private keys or store
handles, and cannot admit actions, install epochs or issue receipts. Product
mutations retain the existing ownership/fencing requirements; decoding values
do not establish any production mutation authority.

The launcher starts an authenticated ephemeral IPv4-loopback service and gives
only the Rust child its random credential. One header binds exact source length
and SHA-256, followed by at most 64 KiB frames. Rust uses a two-slot upload channel
and cancels the RPC when its file-processing scope is cancelled. The platform
checks stream ordering, source limits and digest before decoding; its bounded
workers and inference slots cap outstanding work and pixels. Private temporary
documents are removed on completion/cancellation, and startup removes only
inactive managed documents in the dedicated private cache directory. Rust checks
source/page/engine binding and validates rendered PNG data before returning it.

Java Lite bindings and the gRPC plugin are checksum-pinned in
`release/native_android_platform_toolchain_v1.json`; generation/drift verification
is `scripts/native_android_codegen.py`. Frozen native protocols and corpora are
unchanged. This implementation requires a newly source-bound APK and actual
device workloads; host compilation and old APK evidence cannot qualify it.


## Agent execution signing boundary

`SignControlRequest` adds purpose `AGENT_EXECUTION` and a typed Agent execution
claim. Rust renews the immutable identity through the configured authenticated
Go AgentRunControl endpoint; supplied lease dates cannot establish authority.
Only CLAIMED/EXECUTING work under both live leases can obtain the distinct
`control-agent-execution-grant-v1` Ed25519 domain. The schema has mode
`authoritative`; it cannot substitute for frozen shadow authority/storage grants.

The signed scope contains the request hash/length, plan digest, metadata
index/epoch, claim revision and domain-separated owner/claim-token digests. The
writer fencing counter equals the signed envelope fencingToken and the pinned
Rust authority. Expiry is bounded by both Go action and writer leases and a
300-second maximum. Exact retries revalidate current lease/epoch and return the
original receipt; they never refresh signed dates. No raw credential or signing
private key appears in the canonical receipt. Versioned Protobuf/gRPC transports
typed issuance; canonical JSON bytes are the signed cryptographic document.

Epoch installation remains a separately signed durable Rust operation. Signing
cannot install or advance a local epoch. These phase grants are prerequisites,
not provider effect receipts: actual node dispatch must additionally enforce its
fence/lease, persist an intent and settle or preserve EFFECT_UNKNOWN through
provider-backed reconciliation. The new signed grant alone cannot mark a node
completed or qualify production readiness.


### Agent phase grant refresh

`AgentRunControl.RefreshAuthorization` is an explicit new signing operation for
an already-admitted, still-live phase. Its typed request binds the existing
action fence, run, owner and claim token. Go renews both current authority and
the phase lease before issuance, then rechecks the immutable scope and live
authority after the Rust response. Rust independently renews through the pinned
Go endpoint and requires the exact epoch already installed. The refresh path
never claims an action or installs/advances an epoch.

The operation ID determines separate refresh request/nonce domains. Rust's
durable signature journal binds that identity to the original signed document;
exact retries retain issued/expiry dates and conflicts are rejected. A distinct
operation can issue a new bounded grant for subsequent nodes under the same live
claim. It cannot extend or rewrite an old document, erase an uncertain effect,
re-dispatch a retained node or resurrect expired/cancelled/reconciled authority.
Original custody remains bound to its own grant, and retained effects are read
through their historical query/projection path. Public Agent/DAG integration and
full-product readiness still require separate real workload evidence.


### Native public Agent creation and authoritative DAG controller

The Rust gateway's `POST /api/agent-runs` validates the retained browser request envelope, checks the actual private Go domain authority, and stores sanitized immutable request/status bodies in Rust custody. Only the typed Go `AppendEvent` transaction creates run metadata. Public responses hydrate the actual body references and Go event indices; no caller supplies a signed effect or completion flag.

Authoritative `deepseekd` starts its Go Agent controller with the control lifecycle and drains it before closing the store. It claims existing typed plan/task/synthesis scopes, keeps live phase leases renewed, obtains pinned Rust authorization, refreshes explicitly between nodes, respects dependencies and confirmation stops, ingests independently verified Rust receipts, and uses the existing signed projection/atomic settlement APIs. A committed reservation is resolved only by retained Rust custody; lost or unknown effects cannot grant another provider call. Shadow mode does not start this controller.

The added cloud process gate must start an empty request store, create through the actual native HTTP API, make four controlled provider requests (planner/two dependent tasks/final answer), retain four actual Rust node outcomes and all eight public events, and release all three Go phases. Python only provisions offline test fixtures/reports. This controlled `auto` DAG is separate from real provider, all presets, tool continuation, confirmation/rerun/resume/cancel, platform and complete zero-Python product qualification. The static bootstrap page is an offline API fixture. Full migration remains `NOT_READY`.


### Native public plan confirmation and cancellation

Native Agent creation retains the automatic confirmation rule: auto/plan presets, an explicit confirmation request, and user queries longer than 1800 Unicode characters wait for plan confirmation. The Rust gateway exposes POST /api/agent-runs/{runId}/plan and /cancel through the existing versioned AppendEvent protocol. Rust alone stores the immutable event bodies; Go alone commits the fenced metadata and indexed event history. Confirmation accepts a bounded, validated editable DAG while the run is awaiting_plan, then moves it to running. The second event uses the newly read cursor, so concurrent cancellation or edits cannot silently overwrite it; an invalid edit leaves the plan awaiting confirmation. A repeated plain confirmation of a running run does not schedule another action. Cancellation is sticky and retains unresolved reservations/effects rather than claiming that a remote operation was unapplied.

The cloud public API probe must observe a completed planning action with no task action, leave an entire controller tick without confirmation, POST through the actual public confirmation endpoint, then qualify four controlled upstream calls, four Rust outcomes, nine public events and three settled Go phases. Runtime payload updates, rerun/resume, complete preset parity, uncertain-effect recovery, actual providers and device/default-package qualification remain outstanding. **NOT_READY**.


Native agent planning retains full/code/research/reason/critic static presets and their original dependency/task text. Auto uses the original Unicode keyword and length rules: exactly one signal selects a static plan; no or conflicting signals call the leader planner. Explicit leader continues using the upstream planner. Rust resolves the immutable input and records/attests the planning result inside the existing action/epoch admission and effect journal. Static plans carry an explicit local policy source and never claim an upstream response. Go alone normalizes, confirms, dispatches and settles the plan. Both `agents` (retained planner schema) and `tasks` candidates enter the existing typed signed receipt.

The bounded cloud gate keeps the original public four-request chain and signing/restart probes and adds thirteen real Rust HTTP creation runs covering every preset, static/dynamic auto selection, Unicode length boundaries, explicit and long-query confirmation. Expected plans are offline assertions, never seeded runtime rows. Provider calls, request/body custody, actual normalized dependencies, signed node outcomes and all three Go phase releases must match each run. Controlled providers and bootstrap HTML do not qualify real providers, frontend, platform packages or full migration. Readiness remains NOT_READY.


Native public cancellation verification uses actual Rust POST request custody, Go scheduling and Rust planner effects for both upstream auto and retained static full plans. While awaiting plan confirmation, actual cancel must append one terminal event; a duplicate must preserve the cursor, later confirmation must conflict, and no tasks or synthesis may be admitted. Actual JSON event reads and terminal NDJSON must expose the same durable cancellation. The isolated controlled provider must receive only the original planner call (zero calls for static planning). This bounded proof does not qualify cancellation of an active task, external providers, default CLI/platform packaging or the full migration. Those remain mandatory open work; keep NOT_READY.


The active cancellation safety probe holds the first actual controlled provider task until public cancellation commits, then lets the provider return. The Go controller must drain without admitting the dependent task or synthesis; actual Rust custody must contain the confirmed late task while the cancelled public cursor/NDJSON remain terminal. The original unsettled task resources must stay held. This proves bounded cancellation safety only: cancelled phase recovery and resource resolution require separate authoritative evidence and remain unqualified. No real provider or full migration qualification is inferred.


### Cancelled task custody settlement

A cancelled native task/synthesis phase has a separate `CANCELLED_CONFIRMED` terminal action state. The Go scheduler may observe only its original Rust node dispatches through the existing versioned query/receipt protocol; it issues no new provider grant, node execution, task projection or dependent admission. The typed Go settlement revalidates every retained Rust outcome signature, the cancelled metadata checkpoint, original request/plan scope, live claim and writer fences. It atomically binds an immutable cancellation marker and termination journal before releasing phase reservations. Missing outcomes, stale claims and storage faults retain reservations. This never projects task/run success or declares the remote effect unapplied.

The cloud process gate stops the actual controller while a controlled provider task is in flight, preserves the confirmed late Rust custody and unresolved resources, then starts a new controller owner. Only after the original lease expires may it take over with a new execution epoch, query the original custody, commit the cancellation settlement and release resources. Public cancelled cursor and terminal NDJSON remain unchanged; no dependent task or synthesis is admitted. This bounded task cancellation/recovery proof does not qualify real providers, plan-phase cancellation, tool continuation, full takeover/rollback, default CLI/platform packages or the complete migration. Keep `NOT_READY`.


### Control store v16 cancellation terminal constraint

Schema v16 extends only the action lease terminal CHECK with `CANCELLED_CONFIRMED`. The original v5 table definition and all legacy transition rules stay unchanged. Migration validates v15 first, then copies the complete metadata and lease rows into new strict tables within the existing writer transaction, replaces the old tables, and verifies the exact new schema before recording the version. Resource reservations, action/control journals and immutable lease events retain their original bytes. Failed migration rolls back all changes. The separate cancellation settlement still requires independently verified Rust node custody and cannot declare task success or an unapplied effect. Historical test fixtures now create the actual old lease constraint before testing upgrades. The migration follows [SQLite's generalized table schema change procedure](https://www.sqlite.org/lang_altertable.html#making_other_kinds_of_table_schema_changes); full native and Android tests remain cloud-only.


### Admitted Agent output custody after controller disconnect

After Go has committed a unique node dispatch and Rust has admitted its original permit, task/synthesis provider execution retains an owned future independent of the RPC response. The original send-lease checks and provider timeout remain; a controller disconnect cannot create a new grant, node dispatch or dependent effect. Rust persists actual confirmed output before response publication. Missing output, worker shutdown or panic remains unresolved and cannot authorize a repeated effect. A query maps an unconfirmed DISPATCHING journal to EFFECT_UNKNOWN on the existing protocol without changing the retained journal. Go may settle cancelled custody only through independently verified original receipts under its current fenced lease; public cancellation and its cursor stay final.
