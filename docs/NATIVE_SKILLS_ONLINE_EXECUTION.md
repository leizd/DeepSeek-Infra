The retained contract is all 52 Skill actions and the path-based run endpoint.
An authenticated, legal online run with an available provider credential must
actually execute, preserve provider content/model/usage/diagnostics, apply its
artifact/project policy, and record its real terminal state. Offline content is
not an online result. Python remains an offline oracle only.

Test-only baseline `c45a9c9d` retained parent `6ff4b8ab`'s production implementation.
[Actual run 41370273799](https://github.com/leizd/DeepSeek-Infra/actions/runs/41370273799)
compiled and executed the new case: authentication and owner checks passed, then
the legal online request returned `501 NATIVE_SKILLS_ACTION_NOT_READY` instead of
the required200. That original functional failure is retained. The case uses a production
router request with a real disposable loopback provider socket. It first checks
authentication and Python-owned-store denial without provider calls or partial
trace/artifact writes, then requires an actual successful online call. Later
assertions cover original output bytes and usage, project/artifact/trace/run
records, restart, the path entry with environment credentials and no persistence,
restore fencing, and conclusive provider rejection without another request.
No SQL state is seeded; the trace query is read-only. No real provider key or
production data is used.

The candidate extracts the original chat preparation into a shared function and
uses the same native non-streaming model-cascade/tool execution as public chat.
The original streaming dispatch remains. Skill handlers are asynchronous and
retain every pre-execution owner check. Preparation/request/provider failures
and successes all finish through the existing artifact/project/analytics/trace
path. Output retains the original four fields. The search flag also recognizes
the original `compare_search_results` tool name.

Six stored request fixtures are generated by the original Python `_llm_output`
with an injected capture callable: no network or production execution occurs.
Rust compares its actual request composition for no tools, web search, source
comparison, both searches, memory and browser-policy filtering. The workflow
regenerates the fixtures and compares their bytes before accepting them.

The original20offline HTTP oracle cases, logical state/restart comparisons and
owner/restore denials remain. Their historical extra "valid key must return501
without writes" gap check is replaced by an independent, empty native fixture
and a real local HTTP401provider. It requires exactly one request, native502,
one real failed run/trace, no generated Markdown and no persisted/leaked key.
This failure correctly writes terminal records; it is not reported as no writes.
The offline oracle's original fixture and case count remain unaffected.
All original33Rust checks remain, with one additional mandatory Skill/oracle
step and a report-only artifact; the existing15crate80floor is unchanged.

Native compilation and runtime verification remain in Actions. The candidate is
not qualified until its own exact-source tests and reports pass. Parent platform
or Rust results never qualify this changed source.

This case is not all-Skill parity or full-product readiness. Full original
ownership/recovery/cutover, every retained capability and platform, zero production
Python/server TypeScript, original MCP test engine, complete exact-source
CI/Evidence, coverage, security and performance remain required. **NOT_READY**.
