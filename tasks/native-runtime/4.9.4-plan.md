## Overview

Version 4.9.4 de-authoritizes Python in the default production topology while retaining an explicit,
bounded rollback package (`DEEPSEEK_LEGACY_PYTHON=1`). The default production deployment runs exclusively:
- `deepseek-edge` (Rust)
- `deepseekd` (Go)
- `deepseek-worker` (Rust)
- `frontend` (static assets)

Status: **in progress**. `docker-compose.native.yml` is a target-shape manifest,
not a qualified production topology: the edge image now packages and serves the
built frontend and the worker selects a distinct fail-closed binary target, but
the worker remains loopback-only without an authority channel, `/api/*` is not a
real proxy, and runtime evidence is absent. `deepseekd` is explicitly shadow-only;
static zero-Python text checks do not establish de-authoritization.
