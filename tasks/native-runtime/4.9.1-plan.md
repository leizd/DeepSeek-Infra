## Overview

Version 4.9.1 tracks the Rust Storage and Transfer Plane cutover across 13 data and security domains.
The cutover is still in progress: Python remains the production storage authority until every phase below
has provider-backed evidence. The current native slices implement strict `object-set-v1`, Receipt v4,
Commit v4, signed replica-attestation verification, and the exact sovereign federation transfer journal
with SQLite durability and transactional CAS. Rust now also independently recomputes the complete
`predictive-planning-proof-v1` security binding instead of accepting declared PASS values. These slices
and the autonomous storage Evidence validator now recompute Receipt/Commit provider bytes and bindings.
The Rust proof plane also verifies the complete signed `federated-dr-proof-v1` recovery-capability,
production-restore, cleanup, and immutable-failure semantics, plus bilateral Fleet trust, signer rotation,
signed readiness, and challenge replay semantics. These slices do not yet move payload bytes, execute a
restore, or authorize remote effects. Rust now also reproduces the legacy recovery/process Evidence
validators without treating their static parity corpus as provider execution evidence.
The proof plane also validates retention safety, execution decisions, resilience scores, and
the provider-byte-bound destination of autonomous repair and rebalance.
Repair-worker crash Evidence now also checks process identity, increasing execution epochs,
stable repair-job identity, expired leases, and ordered reconciliation observations.
Blast-radius and atomic-budget Evidence now validates monotonic safety floors and
the observed one-admitted/one-rejected process race without granting control authority.

Static observations are not proof that Rust killed a worker, performed repair, took over a lease,
